\subsection{Common Requirements}

The following requirements apply to every feature of the platform and are therefore not repeated in each use case.

\begin{itemize}
    \item \textbf{Authorisation.} Every endpoint is protected by the server-side permission guard, which checks the method, the path, and the module against the permissions of the caller's role. A hidden button or a disabled menu item is never treated as an access control.
    \item \textbf{Pagination.} Every list endpoint is paginated, with a default page size of 10 items and an explicit page parameter, so that no screen loads an unbounded result set.
    \item \textbf{Deletion.} Records that other records refer to are soft-deleted by setting \texttt{deleted\_at}; a soft-deleted record is excluded from every public listing and from every lookup used by a normal user. Hard deletion is limited to join records such as skills, bookmarks, and reactions.
    \item \textbf{Timestamps.} Creation and modification times are stored in UTC and displayed in the time zone of the browser.
    \item \textbf{Money.} All amounts are stored in the smallest currency unit and displayed with two decimals and an explicit currency; a financial record is never updated in place but is corrected by a new ledger entry.
    \item \textbf{File uploads.} Every uploaded file is validated for type and size on the client before the request is sent and on the server before the file is stored.
    \item \textbf{Language.} Every label, message, and validation error is read from the message catalogue, so that the same screen can be rendered in English and in Vietnamese without a code change.
\end{itemize}
