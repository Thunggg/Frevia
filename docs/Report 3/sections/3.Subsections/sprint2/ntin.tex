\subsubsection{ View Milestone List}

\fnhead{Function Trigger}
An authenticated contract participant (Client or Freelancer) accesses the Contract Detail workspace and views the default Milestones timeline tab.\newline
\textbf{Navigation path:} Dashboard $\rightarrow$ Contracts $\rightarrow$ Contract Detail (\texttt{/contracts/:slug}) $\rightarrow$ Milestones Tab.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client, Freelancer.
      \item \textbf{Secondary Actor:} Administrator (\texttt{ADMIN} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Displays the sequential deliverable roadmap of a contract. Allows participants to view all milestone stages, monitor work progress status (\texttt{PENDING}, \texttt{IN\_PROGRESS}, \texttt{SUBMITTED}, \texttt{CHANGES\_REQUESTED}, \texttt{COMPLETED}), observe escrow funding state (\texttt{UNPAID}, \texttt{FUNDED}, \texttt{RELEASED}), and track upcoming deadlines.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract Detail workspace at \texttt{/contracts/:slug} with active ``Milestones'' tab.
      \item Financial progress banner rendering aggregate budget metrics: Total Budget (\$USD), Escrow Funded Balance, Released Earnings, and Remaining Balance.
      \item Vertical chronological roadmap rendering milestone cards with sequence numbers, titles, delivery due dates, amounts, status badges, and action triggers.
      \item Role-specific contextual action buttons (e.g. ``Fund Milestone'' for Client, ``Start Work'' or ``Submit Work'' for Freelancer).
      \item Filter and status filter pills for quickly locating pending, active, or submitted milestone stages.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The client application requests \texttt{GET /api/contracts/:contractId/milestones}.
      \item \texttt{MilestoneService.getMilestoneList()} validates caller identity: verifies that the user is the contract's Client, assigned Freelancer, or an Admin.
      \item Queries \texttt{prisma.milestone.findMany} filtering by \texttt{contractId} where \texttt{deletedAt = null}.
      \item Orders milestones chronologically by creation sequence and target due date.
      \item Aggregates financial totals: sums funded balances, counts total submissions per milestone, and checks for open dispute flags.
      \item Returns HTTP 200 with the milestone collection and summary metrics.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint2/ntin/ViewMilestoneList.png}{Milestones timeline roadmap screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Top progress section displays a visual progress bar indicating percentage of project milestones approved and funded.
      \item Each milestone card presents a sequence step badge (e.g., Step 1, Step 2), milestone title, deliverable description summary, and dollar amount.
      \item Color-coded badges indicate operational status (\texttt{IN\_PROGRESS} in blue, \texttt{SUBMITTED} in amber, \texttt{COMPLETED} in green).
      \item Expandable accordion toggle allows viewing deliverable details, attached files count, and submission history inline.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{status} & Optional milestone status filter (enum: \texttt{PENDING}, \texttt{IN\_PROGRESS}, \texttt{SUBMITTED}, \texttt{COMPLETED}).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The calling user must be an authorized contract participant or an Administrator.
      \item The contract must exist in the database and not be deleted.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-MS-01: Only active milestones where \texttt{deletedAt = null} shall be returned.
      \item BR-MS-02: Milestones shall be ordered sequentially according to milestone sequence and creation order.
      \item BR-MS-03: Milestones in \texttt{SUBMITTED} or \texttt{CHANGES\_REQUESTED} state shall be automatically highlighted for action.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The user navigates to the Contract Detail workspace and selects the Milestones tab.
      \item The web client submits \texttt{GET /api/contracts/:contractId/milestones}.
      \item The API validates participant access and retrieves active milestones.
      \item The system computes financial totals and deliverable progress percentages.
      \item The client renders the sequential milestone roadmap and role-specific action buttons.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & User is not a participant in the contract. API returns HTTP 403 Forbidden; client displays ``Access denied.''\\ \hline
      A2 & Contract not found. API returns HTTP 404 Not Found; client redirects to error page.\\ \hline
      A3 & Database query fails. API returns HTTP 500; client displays retry banner.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{milestones[]} & Array of milestone records with title, amount, status, paymentStatus, dueDate, and submission count.\\ \hline
      \texttt{financials} & Object summarizing total budget, escrow balance, and released earnings.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Milestone timeline is rendered with current progress and payment statuses.
\end{itemize}

\subsubsection{ View Milestone Detail}

\fnhead{Function Trigger}
A user clicks on a milestone card header, title link, or expansion toggle in the milestone roadmap.\newline
\textbf{Navigation path:} Contract Detail $\rightarrow$ Milestones Tab $\rightarrow$ Click Milestone Card (\texttt{/contracts/:slug/milestones/:id}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client, Freelancer, Administrator.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Expands a milestone to inspect detailed deliverable requirements, acceptance criteria, attached reference files, deliverable submission history, client review feedback, and change request revision notes.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Expanded milestone detail panel or modal view.
      \item Milestone header: sequence number, title, amount, escrow payment badge, and due date countdown timer.
      \item Deliverable specifications section rendering formatted Markdown description of expected work deliverables.
      \item Submissions history accordion displaying all past submission cycles with submission notes and links.
      \item Attached files tray with download links and file size badges.
      \item Review actions bar: ``Approve Milestone'', ``Request Changes'', ``Open Dispute'', or ``Submit Deliverables''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The client issues an HTTP request: \texttt{GET /api/contracts/:contractId/milestones/:id}.
      \item \texttt{MilestoneService.getMilestoneDetail()} verifies authorization for the target contract.
      \item Queries \texttt{prisma.milestone.findUnique} including relation arrays: \texttt{submissions}, \texttt{files}, and dispute links.
      \item Validates that the requested milestone belongs to the designated \texttt{contractId} and has \texttt{deletedAt = null}.
      \item Returns HTTP 200 with the composite milestone entity.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint2/ntin/ViewMilestoneDetail.png}{Milestone detail view screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The panel header renders the milestone title, sequence tag, due date badge, and USD budget badge.
      \item Scope section displays detailed criteria and deliverables required for approval.
      \item Latest submission box displays freelancer submission notes, external preview URL, and deliverable attachments.
      \item If revisions were requested, a feedback callout renders the client's revision instructions.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{id} & Numeric milestone identifier (integer path parameter).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Milestone ID must exist and be a valid child of the specified contract.
      \item Caller must be an authorized contract participant or an Administrator.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-MS-04: Deliverable specifications and acceptance criteria are legally binding once the milestone is funded.
      \item BR-MS-05: Milestone submissions history must preserve all revision cycles for audit traceability.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The user clicks a milestone card in the timeline.
      \item The client requests \texttt{GET /api/contracts/:contractId/milestones/:id}.
      \item The API validates access and loads milestone details with nested submissions and files.
      \item The client expands the milestone panel and renders full deliverable criteria and history.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Milestone not found or deleted. API returns HTTP 404 Not Found; client displays ``Milestone not found.''\\ \hline
      A2 & Caller is not authorized. API returns HTTP 403 Forbidden; access denied.\\ \hline
      A3 & Network connection failure. Client displays error message with retry button.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{milestone} & Full milestone entity including title, description, amount, status, paymentStatus, submissions[], and files[].\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Detailed milestone criteria, files, and submission cycles are displayed.
\end{itemize}

\subsubsection{ Create Milestone}

\fnhead{Function Trigger}
A Client clicks the ``+ Add Milestone'' button in the contract workspace to define a new project milestone.\newline
\textbf{Navigation path:} Contract Workspace $\rightarrow$ Milestones Tab $\rightarrow$ Click ``+ Add Milestone''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a Client to append a new deliverable milestone stage to an existing contract, defining milestone title, deliverables scope, monetary value, and target completion deadline.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item ``Add Milestone'' modal dialog or inline form builder.
      \item Milestone title text field (5--100 characters).
      \item Deliverable description textarea detailing expected tasks and acceptance criteria.
      \item Amount input field formatted in USD with live currency validation.
      \item Due date picker requiring selection of a future completion date.
      \item Action buttons: ``Create Milestone'' and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP request: \texttt{POST /api/contracts/:contractId/milestones} with \texttt{title}, \texttt{description}, \texttt{amount}, and \texttt{dueDate}.
      \item \texttt{MilestoneService.createMilestone()} verifies that caller is the contract's Client.
      \item Checks that contract status is \texttt{PENDING}, \texttt{DRAFT}, or \texttt{ACTIVE}.
      \item Computes next sequential order index.
      \item Persists new \texttt{Milestone} entity with initial status \texttt{PENDING} and \texttt{paymentStatus = UNPAID}.
      \item Inside a transaction, recalculates contract \texttt{totalAmount} to include the new milestone budget.
      \item Dispatches an alert notification to the Freelancer.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint2/ntin/CreateMilestone.png}{Create Milestone dialog}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Dialog features title ``Add New Milestone'' and contract reference header.
      \item Input fields: Milestone Name, Detailed Description, Amount (\$USD), and Due Date picker.
      \item Informational notice notes that adding a milestone increases total contract value.
      \item Footer buttons: ``Cancel'' and ``Add Milestone''.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{title} & Milestone title (string, 5--100 characters).\\ \hline
      \texttt{description} & Detailed deliverables and acceptance requirements (string, 10--2000 characters).\\ \hline
      \texttt{amount} & Monetary milestone value in USD (decimal, minimum 5.00).\\ \hline
      \texttt{dueDate} & Target delivery deadline formatted as ISO 8601 future date.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Only the Client owner of the contract can create milestones.
      \item Contract must not be in \texttt{COMPLETED} or \texttt{CANCELLED} status.
      \item Milestone amount must be positive and at least \$5.00.
      \item Due date must be strictly in the future.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-MS-06: Adding a milestone dynamically updates total contract budget commitments.
      \item BR-MS-07: Newly created milestones are initialized with status \texttt{PENDING} and payment status \texttt{UNPAID}.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The Client clicks ``+ Add Milestone'' in the contract roadmap.
      \item The system opens the Create Milestone dialog.
      \item The Client enters title, description, amount, and due date.
      \item The Client clicks ``Create Milestone''.
      \item The system validates fields, computes sequential index, and persists the milestone.
      \item Contract total budget is updated to reflect the new amount.
      \item The dialog closes, the milestone card is added to the roadmap, and the Freelancer is notified.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Amount is less than 5.00 USD. API returns HTTP 422 with validation error.\\ \hline
      A2 & Due date is in the past. API returns HTTP 422; displays ``Due date must be in the future.''\\ \hline
      A3 & Caller is not the Client owner. API returns HTTP 403 Forbidden; access denied.\\ \hline
      A4 & Contract is completed or cancelled. API returns HTTP 422; creation rejected.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{milestone} & Created milestone entity with generated ID, status, and timestamps.\\ \hline
      \texttt{contractTotal} & Updated aggregated contract budget commitment.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item New milestone record created with status \texttt{PENDING}.
      \item Contract total budget updated.
      \item Freelancer notified of the new milestone.
\end{itemize}

\subsubsection{ Update Milestone}

\fnhead{Function Trigger}
A Client clicks the ``Edit'' action on an unfunded or pending milestone card.\newline
\textbf{Navigation path:} Contract Detail $\rightarrow$ Milestones Tab $\rightarrow$ Milestone Card Menu $\rightarrow$ Click ``Edit Milestone''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a Client to adjust deliverable descriptions, milestone titles, budget allocations, or deadline dates on milestones that have not yet been funded or locked into active escrow execution.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Edit Milestone modal pre-populated with current milestone properties.
      \item Title input, Markdown deliverables textarea, amount input, and due date picker.
      \item Action buttons: ``Save Changes'' and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP request: \texttt{PATCH /api/contracts/:contractId/milestones/:id} with updated attributes.
      \item \texttt{MilestoneService.updateMilestone()} verifies that caller is the contract's Client.
      \item Checks that milestone payment status is \texttt{UNPAID}; funded milestones cannot have their amounts altered without refund.
      \item Updates milestone attributes in the database and recalculates contract total budget.
      \item Records update activity and notifies the Freelancer.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint2/ntin/UpdateMilestone.png}{Edit Milestone modal}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Modal displays header ``Edit Milestone \#Step''.
      \item Form fields display existing milestone data with edit focus.
      \item Footer renders secondary ``Discard'' and primary ``Save Changes'' buttons.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{id} & Numeric milestone identifier (integer path parameter).\\ \hline
      \texttt{title} & Updated milestone title (string, optional).\\ \hline
      \texttt{description} & Updated deliverable description (string, optional).\\ \hline
      \texttt{amount} & Updated monetary value (decimal, optional).\\ \hline
      \texttt{dueDate} & Updated deadline date (ISO 8601 future date, optional).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be the contract's Client.
      \item Milestone must reside in \texttt{UNPAID} payment status.
      \item Due date must be set in the future.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-MS-08: Milestones that have already been funded in escrow cannot be modified without formal cancellation or refund.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Client selects ``Edit Milestone'' on an unfunded milestone card.
      \item The system displays the edit modal with current attributes.
      \item Client modifies fields and clicks ``Save Changes''.
      \item System validates inputs and updates database records.
      \item Updated milestone is rendered and Freelancer is notified.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Milestone is already funded. API returns HTTP 422 with error \texttt{MilestoneAlreadyFundedException}; editing locked.\\ \hline
      A2 & Caller is not the Client. API returns HTTP 403 Forbidden; access denied.\\ \hline
      A3 & Invalid due date provided. System highlights date error.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{milestone} & Updated milestone record with revised attributes.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Milestone attributes updated in database.
      \item Freelancer notified of changes.
\end{itemize}

\subsubsection{ Delete Milestone}

\fnhead{Function Trigger}
A Client clicks the ``Delete Milestone'' action on an unfunded milestone card.\newline
\textbf{Navigation path:} Contract Detail $\rightarrow$ Milestones Tab $\rightarrow$ Milestone Menu $\rightarrow$ Click ``Delete Milestone''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a Client to remove an unnecessary or cancelled milestone stage from a contract before it has been funded in escrow.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Delete action option in milestone card contextual menu.
      \item Confirmation dialog: ``Are you sure you want to delete this milestone? Total contract value will be reduced.''.
      \item Action buttons: ``Delete Milestone'' (destructive red) and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP request: \texttt{DELETE /api/contracts/:contractId/milestones/:id}.
      \item \texttt{MilestoneService.deleteMilestone()} validates caller is the contract's Client.
      \item Checks that milestone payment status is strictly \texttt{UNPAID}; funded milestones cannot be deleted.
      \item Soft-deletes milestone by setting \texttt{deletedAt = new Date()}.
      \item Adjusts contract \texttt{totalAmount} downwards to exclude the deleted milestone value.
      \item Returns HTTP 200 with deletion confirmation.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint2/ntin/DeleteMilestone.png}{Delete Milestone confirmation dialog}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Modal displays red trash icon and heading ``Delete Milestone''.
      \item Message warns that deleting removes the deliverable stage and deducts its amount from total budget.
      \item Footer buttons: ``Cancel'' and ``Confirm Delete''.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{id} & Numeric milestone identifier (integer path parameter).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be the Client owner of the contract.
      \item Milestone must reside in \texttt{UNPAID} payment status.
      \item At least one milestone must remain on the contract.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-MS-09: Funded milestones cannot be deleted; they must be refunded or completed.
      \item BR-MS-10: Deleting a milestone reduces the aggregate contract budget commitment.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Client clicks ``Delete Milestone'' on an unfunded milestone card.
      \item The system opens the confirmation dialog.
      \item Client clicks ``Confirm Delete''.
      \item System marks milestone with \texttt{deletedAt = now()} and recalculates contract total.
      \item Dialog closes, card is removed from roadmap, and success notification appears.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Milestone is funded in escrow. API returns HTTP 422 with error \texttt{CannotDeleteFundedMilestoneException}; deletion blocked.\\ \hline
      A2 & Attempt to delete the only remaining milestone. API returns HTTP 422; contracts must have at least one milestone.\\ \hline
      A3 & Caller is not the Client. API returns HTTP 403 Forbidden; access denied.\\ \hline

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]

      \item \textbf{Secondary Actor:} Freelancer (\texttt{FREELANCER} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Stripe Connect payment release service, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Formally accepts submitted milestone deliverables as complete and satisfactory. Automatically triggers escrow fund release via Stripe Connect, transferring milestone earnings to the Freelancer's account minus platform service fees, and marks the milestone as \texttt{COMPLETED}.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Prominent green ``Approve Milestone'' action button on submitted milestone card.
      \item Approval confirmation modal displaying milestone deliverable summary, escrow release amount, and platform fee breakdown.

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP request: \texttt{PATCH /api/contracts/:contractId/milestones/:milestoneId/submissions/:id/approve}.
      \item \texttt{MilestoneSubmissionService.approveMilestone()} verifies caller is the contract's Client.
      \item Verifies milestone is in \texttt{SUBMITTED} or \texttt{CHANGES\_REQUESTED} status, and escrow \texttt{paymentStatus = FUNDED}.
      \item Checks that Freelancer has completed Stripe Connect onboarding.
      \item Inside a database transaction:
            \begin{itemize}[leftmargin=1.6em,topsep=2pt,itemsep=2pt,parsep=0pt]
                  \item Transitions submission status to \texttt{APPROVED}.
                  \item Transitions milestone status to \texttt{COMPLETED} and sets \texttt{paymentStatus = RELEASED}.
                  \item Invokes Stripe Transfer to release net earnings to freelancer's connected account.
                  \item Records ledger transaction records (\texttt{ESCROW\_RELEASE}).
            \end{itemize}
      \item Dispatches immediate payment receipt notification to Freelancer.
\end{itemize}

      \item \textbf{Secondary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Formally delivers completed milestone work to the Client for inspection. The Freelancer includes submission notes, external demo/staging URLs, and deliverable attachments, transitioning milestone status to \texttt{SUBMITTED}.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Submit Work modal dialog.
      \item Submission notes textarea (Markdown supported, 10--2000 characters).

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Freelancer submits an HTTP request: \texttt{POST /api/contracts/:contractId/milestones/:milestoneId/submissions} with \texttt{notes}, \texttt{externalLink}, and \texttt{fileIds}.

      \item Checks milestone status: must be \texttt{IN\_PROGRESS} or \texttt{CHANGES\_REQUESTED}, and escrow must be \texttt{FUNDED}.
      \item Persists new \texttt{MilestoneSubmission} record with status \texttt{PENDING\_REVIEW}.
      \item Transitions milestone status to \texttt{SUBMITTED}.
      \item Dispatches an urgent review notification to the Client with deliverable summary.
\end{itemize}

      \item Milestone status must be \texttt{IN\_PROGRESS} or \texttt{CHANGES\_REQUESTED}.
      \item Milestone escrow must be in \texttt{FUNDED} status.

      \item Freelancer clicks ``Submit Work'' on an in-progress milestone card.
      \item System displays Submit Milestone modal.
      \item Freelancer types submission notes, attaches files, and inputs optional demo link.
      \item Freelancer clicks ``Submit for Approval''.
      \item System validates fields, creates submission entity, and sets milestone status to \texttt{SUBMITTED}.

      A2 & Milestone escrow is unfunded. API returns HTTP 422; submission rejected.\\ \hline
      A3 & Caller is not the Freelancer. API returns HTTP 403 Forbidden; access denied.\\ \hline

\end{flowtable}
