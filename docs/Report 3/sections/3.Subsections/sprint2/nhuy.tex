\subsection{Identity Verification}
\Needspace{10\baselineskip}
\subsubsection{Function: Upload Identity Documents (UC-18.01)}
\label{fn:nhuy-uc-18-01}

\Needspace{7\baselineskip}
\fnhead{Function Trigger}
The actor selects Upload Identity Documents. Navigation: /account-profile (Identity Verification tab).

\Needspace{7\baselineskip}
\fnhead{Function Description}
\Needspace{5\baselineskip}
\sublabel{Actors / Roles}
Freelancer.
\Needspace{5\baselineskip}
\sublabel{Purpose}
Validate the active-request constraint, securely store the submitted evidence, and record the verification outcome for review.
\Needspace{5\baselineskip}
\sublabel{Interface and Data Processing}
{\small\texttt{POST /\allowbreak{}identity-verifications/\allowbreak{}ai-check;\allowbreak{} POST /\allowbreak{}identity-verifications/\allowbreak{}documents}}. The browser calls the Next.js BFF, which forwards authenticated requests to the NestJS API. The server derives the acting user from authentication and accesses User, IdVerificationDocument, FreelancerProfile. Route IDs are validated independently from owner IDs.

\Needspace{7\baselineskip}
\fnhead{Screen Layout (Mock-up Description)}
\begin{center}
\fbox{\begin{minipage}{0.88\linewidth}
\textbf{Upload Identity Documents}\par\smallskip
Document-type and front/back selectors; webcam liveness panel for AI submission; Submit; latest status badge, submission history and rejection instructions.\par\smallskip
\textit{Schematic interface description, not an application screenshot.}
\end{minipage}}
\end{center}

\Needspace{7\baselineskip}
\Needspace{18\baselineskip}
\fnhead{Function Details}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Input Data}
\begin{specdatatable}{Data}{Definition}
documentType & Supported identity-document type. \\ \hline
front / back & Document images; both sides where required by document type. \\ \hline
selfie / liveness & Selfie and captured liveness frames for the AI path. \\ \hline
document file & Manual-path JPEG, PNG, WebP or PDF; maximum 5 MB under the identity business rule. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Validation and Business Rules}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Only an authenticated freelancer submits or reads their own verification status.
\item At most one active PENDING or APPROVED request is allowed per freelancer.
\item Documents are confidential; storage delivery and file endpoints must enforce authorization.
\item AI success creates PENDING for administrator review; AI rejection records REJECTED with a reason. AI transport failure must not create a successful request.
\item Rejected users may resubmit after correcting the stated problem. NOT\_SUBMITTED is displayed when API status is null.
\end{itemize}
\Needspace{5\baselineskip}
\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item The actor opens /account-profile (Identity Verification tab) and selects Upload Identity Documents.
\item The application presents the current values or action confirmation; the actor supplies the required data and submits.
\item The API checks authentication where required, authorization, resource existence and input validity.
\item Validate the active-request constraint, securely store the submitted evidence, and record the verification outcome for review.
\item After the transaction succeeds, the screen displays the result and reloads affected data; a pending revision is labeled as awaiting review.
\end{enumerate}
\Needspace{5\baselineskip}
\sublabel{Alternative Flow}
Cancel before submission closes the form or confirmation without persisting changes. On failure, preserve user input for correction and retry.
\Needspace{5\baselineskip}
\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
E1 & Missing or expired authentication, or insufficient role/ownership: deny the operation and do not change data. \\ \hline
E2 & Missing, deleted or inaccessible resource: show a not-found result. \\ \hline
E3 & Invalid input, duplicate relationship, or invalid workflow state: explain the problem and retain the entered values. \\ \hline
E4 & Database, network or storage failure: report a retryable error; do not report success or terminate the API process. \\ \hline
E5 & An active PENDING/APPROVED request blocks resubmission. An unavailable AI service is reported without creating a successful verification record. \\ \hline
\end{flowtable}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Output Data}
\begin{specdatatable}{Data}{Definition}
Result & Validate the active-request constraint, securely store the submitted evidence, and record the verification outcome for review. \\ \hline
Failure & Structured error without sensitive data; no successful UI state when the operation failed. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Acceptance Criteria}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Successful upload identity documents produces the documented response and survives a reload where data is persisted.
\item An unauthorized actor cannot access or modify the resource.
\item Invalid input and missing resources do not create a false success state or expose sensitive data.
\end{itemize}
