\subsubsection{ Upload Identity Documents}

\fnhead{Function Trigger}
The actor selects Upload Identity Documents.\newline
\textbf{Navigation path:} Home $\rightarrow$ \texttt{/account-profile (Identity Verification tab).}

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Freelancer.
    \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia BFF proxy (\texttt{/api/backend}), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Validate the active-request constraint, securely store the submitted evidence, and record the verification outcome for review.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Document-type and front/back selectors.
    \item Webcam liveness panel for AI submission.
    \item Submit.
    \item Latest status badge, submission history and rejection instructions.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item The client web application issues an HTTP request to \texttt{POST /identity-verifications/ai-check; POST /identity-verifications/documents} via the Next.js BFF proxy.
    \item NestJS guards verify JWT authentication and validate role-based access permissions.
    \item The backend service queries or updates entities in PostgreSQL using Prisma ORM.
    \item The API returns the structured JSON payload and handles domain invariants consistently.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint2/nhuy/Upload Identity Documents.png}{Upload Identity Documents interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Document-type and front/back selectors.
    \item Webcam liveness panel for AI submission.
    \item Submit.
    \item Latest status badge, submission history and rejection instructions.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
documentType & Supported identity-document type.\\ \hline
front / back & Document images; both sides where required by document type.\\ \hline
selfie / liveness & Selfie and captured liveness frames for the AI path.\\ \hline
document file & Manual-path JPEG, PNG, WebP or PDF; maximum 5 MB under the identity business rule.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Rejected users may resubmit after correcting the stated problem. NOT\_SUBMITTED is displayed when API status is null.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-1801-01: Only an authenticated freelancer submits or reads their own verification status.
    \item BR-1801-02: At most one active PENDING or APPROVED request is allowed per freelancer.
    \item BR-1801-03: Documents are confidential; storage delivery and file endpoints must enforce authorization.
    \item BR-1801-04: AI success creates PENDING for administrator review; AI rejection records REJECTED with a reason. AI transport failure must not create a successful request.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item The actor opens \texttt{/account-profile} (Identity Verification tab) and selects Upload Identity Documents.
    \item The application presents the current values or action confirmation; the actor supplies the required data and submits.
    \item The API checks authentication where required, authorization, resource existence and input validity.
    \item Validate the active-request constraint, securely store the submitted evidence, and record the verification outcome for review.
    \item After the transaction succeeds, the screen displays the result and reloads affected data; a pending revision is labeled as awaiting review.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Missing or expired authentication token. The system returns HTTP 401 Unauthorized and prompts re-authentication.\\ \hline
A2 & Insufficient permissions or role unauthorized. The request is rejected with HTTP 403 Forbidden.\\ \hline
A3 & Target resource not found or soft-deleted. The system returns HTTP 404 Not Found.\\ \hline
A4 & Validation error or malformed payload. The system returns HTTP 400 Bad Request with field validation details.\\ \hline
A5 & Database connectivity failure or unexpected internal exception. The transaction rolls back and returns HTTP 500.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
Result & Validate the active-request constraint, securely store the submitted evidence, and record the verification outcome for review.\\ \hline
Failure & Structured error without sensitive data; no successful UI state when the operation failed.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Successful upload identity documents produces the documented response and survives a reload where data is persisted.
    \item An unauthorized actor cannot access or modify the resource.
    \item Invalid input and missing resources do not create a false success state or expose sensitive data.
\end{itemize}
