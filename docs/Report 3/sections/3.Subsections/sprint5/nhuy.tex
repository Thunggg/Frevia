\subsubsection{ View Pending Profile Update Request List}

\fnhead{Function Trigger}
The actor selects View Pending Profile Update Request List.\newline
\textbf{Navigation path:} Home $\rightarrow$ \texttt{/\allowbreak{}admin/\allowbreak{}profile-\allowbreak{}revisions} or \texttt{/\allowbreak{}expert/\allowbreak{}profile.}

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Admin.
    \item \textbf{Supporting Systems:} Frevia Web (Next.js), Frevia BFF proxy, Frevia REST API (NestJS), Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Filter and paginate revisions, defaulting the review workflow to pending requests.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Admin filter bar and revision table.
    \item Current/proposed comparison panel.
    \item Approve/Reject controls and note field.
    \item Expert form with submission status.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item The client issues an HTTP request to \texttt{GET /\allowbreak{}admin/\allowbreak{}profile-\allowbreak{}revisions} via Next.js BFF proxy.
    \item NestJS guards verify JWT authentication and validate role-based access permissions.
    \item The backend service queries or updates entities in PostgreSQL using Prisma ORM.
    \item The API returns the structured JSON payload and handles domain invariants consistently.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint5/nhuy/View Pending Profile Update Request List.png}{View Pending Profile Update Request List interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Admin filter bar and revision table.
    \item Current/proposed comparison panel.
    \item Approve/Reject controls and note field.
    \item Expert form with submission status.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
Selection & Validated page, limit, search, status and profileType filters.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Approval applies validated proposed data to the correct subtype; rejection retains existing public data.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-4701-01: Only an authorized administrator can inspect or decide profile revisions.
    \item BR-4701-02: Only PENDING revisions may be approved or rejected. Decision and profile writes are transactional.
    \item BR-4701-03: Record reviewer, decision time and notes; preserve history and notify the requester.
    \item BR-4701-04: An Expert submits their own update as a pending revision. Administrative expert editing is a separate authorized operation.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item The actor opens \texttt{/\allowbreak{}admin/\allowbreak{}profile-\allowbreak{}revisions}; \texttt{/\allowbreak{}expert/\allowbreak{}profile} and selects View Pending Profile Update Request List.
    \item The application submits the selected identifier or list filters.
    \item The API checks authentication where required, authorization, resource existence and input validity.
    \item Filter and paginate revisions, defaulting the review workflow to pending requests.
    \item The screen renders the response, or an explicit empty state for a valid empty collection.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Missing or expired authentication token. Returns HTTP 401 Unauthorized.\\ \hline
A2 & Insufficient permissions or role unauthorized. Returns HTTP 403 Forbidden.\\ \hline
A3 & Target resource not found or soft-deleted. Returns HTTP 404 Not Found.\\ \hline
A4 & Validation error or malformed payload. Returns HTTP 400 Bad Request.\\ \hline
A5 & Database connectivity failure or server error. Returns HTTP 500.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
Result & Filter and paginate revisions, defaulting the review workflow to pending requests.\\ \hline
Failure & Structured error without sensitive data; no successful UI state when the operation failed.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Successful view pending profile update request list produces the documented response and survives a reload where data is persisted.
    \item An unauthorized actor cannot access or modify the resource.
    \item Invalid input and missing resources do not create a false success state or expose sensitive data.
\end{itemize}
