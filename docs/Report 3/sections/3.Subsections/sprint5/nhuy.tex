\subsubsection{Function: View Pending Profile Update Request List (UC-47.01)}
\label{fn:nhuy-uc-47-01}

\Needspace{7\baselineskip}
\fnhead{Function Trigger}
The actor selects View Pending Profile Update Request List. Navigation: /admin/profile-revisions; /expert/profile.

\Needspace{7\baselineskip}
\fnhead{Function Description}
\Needspace{5\baselineskip}
\sublabel{Actors / Roles}
Admin.
\Needspace{5\baselineskip}
\sublabel{Purpose}
Filter and paginate revisions, defaulting the review workflow to pending requests.
\Needspace{5\baselineskip}
\sublabel{Interface and Data Processing}
{\small\texttt{GET /\allowbreak{}admin/\allowbreak{}profile-revisions}}. The browser calls the Next.js BFF, which forwards authenticated requests to the NestJS API. The server derives the acting user from authentication and accesses ProfileRevision, Profile, FreelancerProfile, ClientProfile, Expert, Notification. Route IDs are validated independently from owner IDs.

\Needspace{7\baselineskip}
\fnhead{Screen Layout (Mock-up Description)}
\begin{center}
\fbox{\begin{minipage}{0.88\linewidth}
\textbf{View Pending Profile Update Request List}\par\smallskip
Admin filter bar and revision table; current/proposed comparison panel; Approve/Reject controls and note field; Expert form with submission status.\par\smallskip
\textit{Schematic interface description, not an application screenshot.}
\end{minipage}}
\end{center}

\Needspace{7\baselineskip}
\Needspace{18\baselineskip}
\fnhead{Function Details}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Input Data}
\begin{specdatatable}{Data}{Definition}
Selection & Validated page, limit, search, status and profileType filters. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Validation and Business Rules}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Only an authorized administrator can inspect or decide profile revisions.
\item Only PENDING revisions may be approved or rejected. Decision and profile writes are transactional.
\item Approval applies validated proposed data to the correct subtype; rejection retains existing public data.
\item Record reviewer, decision time and notes; preserve history and notify the requester.
\item An Expert submits their own update as a pending revision. Administrative expert editing is a separate authorized operation.
\end{itemize}
\Needspace{5\baselineskip}
\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item The actor opens /admin/profile-revisions; /expert/profile and selects View Pending Profile Update Request List.
\item The application submits the selected identifier or list filters.
\item The API checks authentication where required, authorization, resource existence and input validity.
\item Filter and paginate revisions, defaulting the review workflow to pending requests.
\item The screen renders the response, or an explicit empty state for a valid empty collection.
\end{enumerate}
\Needspace{5\baselineskip}
\sublabel{Alternative Flow}
Show an informative empty state for a valid empty result and allow retry after a transport failure.
\Needspace{5\baselineskip}
\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
E1 & Missing or expired authentication, or insufficient role/ownership: deny the operation and do not change data. \\ \hline
E2 & Missing, deleted or inaccessible resource: show a not-found result. \\ \hline
A1 & A valid empty collection displays an empty state; it must not be treated as a missing account. \\ \hline
E4 & Database, network or storage failure: report a retryable error; do not report success or terminate the API process. \\ \hline
\end{flowtable}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Output Data}
\begin{specdatatable}{Data}{Definition}
Result & Filter and paginate revisions, defaulting the review workflow to pending requests. \\ \hline
Failure & Structured error without sensitive data; no successful UI state when the operation failed. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Acceptance Criteria}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Successful view pending profile update request list produces the documented response and survives a reload where data is persisted.
\item An unauthorized actor cannot access or modify the resource.
\item Invalid input and missing resources do not create a false success state or expose sensitive data.
\end{itemize}
