% UC-13.01: Create Contract

\Needspace{12\baselineskip}
\subsubsection{ Create Contract}

\fnhead{Function Trigger}
A Client initiates contract creation by clicking the ``Hire'' / ``Create Contract'' action button on a submitted or hired job proposal.\newline
\textbf{Navigation path:} Client Workspace $\rightarrow$ My Jobs $\rightarrow$ Proposals (\texttt{/\allowbreak{}client/\allowbreak{}jobs/\allowbreak{}:\allowbreak{}id/\allowbreak{}proposals}) $\rightarrow$ Click ``Hire''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Secondary Actor:} Freelancer (\texttt{FREELANCER} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia BFF proxy (\texttt{/api/backend}), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a Client to establish a formal legally binding freelance agreement with a selected Freelancer following proposal acceptance. The client configures project scope, contractual clauses, payment milestones, budget allocation, platform service fees, and target delivery deadlines before dispatching the contract for review.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract creation dialog accessed directly from the proposal hiring flow at \texttt{/\allowbreak{}client/\allowbreak{}jobs/\allowbreak{}:\allowbreak{}id/\allowbreak{}proposals}.
      \item Proposal summary displaying job title, freelancer profile snapshot, bid amount, and estimated duration.
      \item Contract terms textarea (\texttt{terms}), contract expiration date picker (\texttt{expiresAt}), and total contract budget (\texttt{totalAmount}).
      \item Milestone dynamic builder supporting addition and removal of deliverable milestones (\texttt{title}, \texttt{description}, \texttt{amount}, \texttt{dueDate}).
      \item Financial breakdown summary displaying total milestone budget, the 3\% client platform fee (\texttt{clientPlatformFee}), and freelancer 5\% payout fee.
      \item Primary action button: ``Create Contract''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The client submits an HTTP request: \texttt{POST /\allowbreak{}api/\allowbreak{}contracts} with payload containing \texttt{proposalId}, \texttt{totalAmount}, optional \texttt{terms}, required \texttt{expiresAt}, and optional \texttt{milestones}.
      \item The backend \texttt{AccessTokenGuard} validates the Client's JWT token, and \texttt{PermissionGuard} verifies \texttt{CLIENT} authorization.
      \item \texttt{ContractService.createContract()} queries the proposal: verifies that the proposal exists, belongs to a job owned by the calling client, has status \texttt{SUBMITTED} or \texttt{HIRED}, and that hiring slots remain available (\texttt{positionsFilled < positionsRequired}).
      \item If milestones are provided, the service verifies each milestone \texttt{dueDate} does not exceed contract \texttt{expiresAt} and that milestone amounts sum to \texttt{totalAmount} exactly (within 0.01 tolerance); otherwise, a single default milestone is created.
      \item A URL-friendly unique \texttt{slug} is generated from the job title and random entropy.
      \item Inside a database transaction, \texttt{ContractRepository} persists the \texttt{Contract} entity with initial status \texttt{AWAITING\_PAYMENT} and 3\% \texttt{clientPlatformFee}, creates \texttt{Milestone} records with status \texttt{PENDING} and \texttt{paymentStatus = PENDING}, and transitions proposal status to \texttt{HIRED}.
      \item An in-app notification is sent to the Freelancer inviting them to review the contract offer.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ntin/CreateContract.png}{Create Contract screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The modal/page header displays the contract creation title and associated job reference.
      \item The form contains contract \texttt{expiresAt}, \texttt{terms} textarea, total amount input, and milestone configuration list with ``+ Add Milestone'' button.
      \item Each milestone block renders inputs for milestone title, deliverable description, monetary amount in USD, and completion due date picker.
      \item The financial summary displays milestone subtotal, the 3\% client platform fee, and total contract commitment.
      \item Footer provides ``Cancel'' and ``Create Contract'' action triggers.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{proposalId} & Unique numeric identifier of the eligible job proposal (integer).\\ \hline
      \texttt{totalAmount} & Total contractual budget in USD (positive number).\\ \hline
      \texttt{terms} & Detailed contract scope, deliverables, and legal clauses (string, optional).\\ \hline
      \texttt{expiresAt} & Contract expiration / deadline formatted as future ISO 8601 datetime (required).\\ \hline
      \texttt{milestones} & Optional array of milestone objects containing \texttt{title}, optional \texttt{description}, positive \texttt{amount}, and future \texttt{dueDate}.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The calling user must be the verified owner (Client) of the associated job posting.
      \item The proposal must be in \texttt{SUBMITTED} or \texttt{HIRED} status and not already linked to a contract, and job \texttt{positionsFilled < positionsRequired}.
      \item \texttt{totalAmount} must be strictly positive, and when milestones are supplied, their amounts must sum to \texttt{totalAmount}.
      \item \texttt{expiresAt} and every milestone \texttt{dueDate} must be strictly in the future, with each \texttt{dueDate} not exceeding \texttt{expiresAt}.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-CT-01: Only users authenticated with the \texttt{CLIENT} role shall create new contracts.
      \item BR-CT-02: When milestones are specified, total contract budget shall strictly match the aggregate sum of all milestone amounts.
      \item BR-CT-03: Creating a contract locks the linked proposal (\texttt{HIRED}), preventing duplicate contracts on the same proposal.
      \item BR-CT-04: New contracts are initialized in \texttt{AWAITING\_PAYMENT} status (3\% client platform fee) until the client authorizes the Stripe payment hold (\texttt{PENDING\_SIGN}), after which sequential Client and Freelancer signatures activate execution.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The Client navigates to the job proposals list and clicks ``Hire / Create Contract''.
      \item The web application loads the contract creation dialog with pre-populated proposal data.
      \item The Client reviews project scope, customizes terms, sets \texttt{expiresAt}, and defines deliverable milestones.
      \item The Client clicks ``Create Contract''.
      \item The system validates input fields, milestone total equality, and deadline bounds.
      \item The backend persists the contract (\texttt{AWAITING\_PAYMENT}) and milestone records (\texttt{PENDING}) inside a database transaction.
      \item The linked proposal is transitioned to \texttt{HIRED} state.
      \item The system dispatches a notification to the Freelancer and opens the Contract Detail workspace.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & The sum of milestone amounts does not match \texttt{totalAmount}. The API returns HTTP 422 Unprocessable Entity with \texttt{MilestoneAmountMismatchException}.\\ \hline
      A2 & The specified proposal already has a contract or is not in an actionable status. The API returns HTTP 409 Conflict (\texttt{ContractAlreadyExistsException}) or HTTP 422 (\texttt{ProposalNotActionableException}).\\ \hline
      A3 & \texttt{expiresAt} is missing/past or a milestone \texttt{dueDate} exceeds \texttt{expiresAt}. The API returns HTTP 422 (\texttt{ContractExpiresAtRequiredException} or \texttt{MilestoneDueDateExceedsContractException}).\\ \hline
      A4 & The calling user is not the owner of the job. The backend rejects the request with HTTP 403 Forbidden (\texttt{ContractForbiddenException}).\\ \hline
      A5 & All job positions are already filled. The backend rejects contract creation with HTTP 422 (\texttt{ProposalJobPositionsFilledException}).\\ \hline
      A6 & Database failure during transaction persistence. The transaction rolls back and returns HTTP 500 (\texttt{FailedToCreateContractException}).\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{id} & Unique auto-incrementing integer identifier of the created contract.\\ \hline
      \texttt{slug} & Unique URL-friendly slug identifier for bookmarking and routing.\\ \hline
      \texttt{status} & Initial operational contract state (\texttt{AWAITING\_PAYMENT}).\\ \hline
      \texttt{totalAmount} & Final aggregated contractual budget committed by the client.\\ \hline
      \texttt{clientPlatformFee} & Calculated 3\% client platform service fee.\\ \hline
      \texttt{milestones[]} & Array of created milestone entities with status \texttt{PENDING} and due dates.\\ \hline
      \texttt{createdAt} & ISO 8601 creation timestamp.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item A new \texttt{Contract} entity is persisted with status \texttt{AWAITING\_PAYMENT}.
      \item Milestone records are linked to the contract with \texttt{status = PENDING} and \texttt{paymentStatus = PENDING}.
      \item An invitation notification is queued for the Freelancer.
\end{itemize}

\Needspace{12\baselineskip}
\subsubsection{ Update Contract}

\fnhead{Function Trigger}
A Client clicks the ``Edit Terms'' button on a contract detail workspace to revise agreement specifications before activation.\newline
\textbf{Navigation path:} Client Workspace $\rightarrow$ Contracts $\rightarrow$ Contract Detail (\texttt{/\allowbreak{}client/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}slug}) $\rightarrow$ Click ``Edit Terms''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Secondary Actor:} Freelancer (\texttt{FREELANCER} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a Client to modify contract clauses, milestone budgets, scopes, and target completion dates while the contract remains in pending negotiation. Updating terms ensures flexibility to adapt to mutual renegotiations before formal signature activation.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract terms editor modal pre-populated with existing \texttt{totalAmount}, \texttt{terms}, and \texttt{expiresAt}.
      \item Milestone amounts and due dates are managed separately via the Milestone Management endpoints prior to contract activation.
      \item Interactive budget summary displaying \texttt{totalAmount} (locked once payment hold is authorized).
      \item Action buttons: ``Save Changes'' and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The client submits an HTTP request: \texttt{PATCH /\allowbreak{}api/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}id} with optional \texttt{totalAmount}, \texttt{terms}, and \texttt{expiresAt}.
      \item {\sloppy \texttt{Contract\allowbreak{}Service.\allowbreak{}update\allowbreak{}Contract()} checks ownership against \texttt{contract.clientId}.\par}
      \item {\sloppy The service validates that contract status is strictly \texttt{AWAITING\_\allowbreak{}PAYMENT} or \texttt{PENDING\_\allowbreak{}SIGN}; active, completed, or cancelled contracts are rejected (\texttt{Contract\allowbreak{}Not\allowbreak{}Pending\allowbreak{}Sign\allowbreak{}Exception}).\par}
      \item {\sloppy If a Stripe payment hold (\texttt{hold\allowbreak{}Payment\allowbreak{}Intent\allowbreak{}Id}) is already attached, attempts to alter \texttt{total\allowbreak{}Amount} are rejected; updates to \texttt{expires\allowbreak{}At} verify all milestone due dates remain valid.\par}
      \item {\sloppy Updates modified \texttt{Contract} fields inside \texttt{Contract\allowbreak{}Repository.\allowbreak{}update\allowbreak{}Contract()}.\par}
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ntin/UpdateContract.png}{Update Contract Terms screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The modal header displays the contract reference and current status badge.
      \item Form fields display editable contract total budget (when no hold exists), contract expiration date, and terms textarea.
      \item Footer contains ``Cancel'' secondary button and ``Save Changes'' primary button.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Unique numeric contract identifier passed as path parameter (integer).\\ \hline
      \texttt{totalAmount} & Revised positive contract budget (number, optional; locked once \texttt{holdPaymentIntentId} is set).\\ \hline
      \texttt{terms} & Revised contract terms and scope text (string, optional).\\ \hline
      \texttt{expiresAt} & Revised future expiration timestamp (ISO 8601 string, optional; must not precede milestone due dates).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Only the Client who created the contract is permitted to update its terms.
      \item The contract must currently reside in \texttt{AWAITING\_PAYMENT} or \texttt{PENDING\_SIGN} status.
      \item \texttt{totalAmount} cannot change once a Stripe payment hold has been authorized.
      \item If \texttt{expiresAt} changes, all existing milestone due dates must remain on or before the new deadline.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-CT-05: Contract updates in \texttt{AWAITING\_PAYMENT} or \texttt{PENDING\_SIGN} adjust \texttt{totalAmount} (pre-hold), \texttt{terms}, and \texttt{expiresAt} while preserving existing milestone definitions.
      \item BR-CT-06: Active, completed, or cancelled contracts cannot be modified directly.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The Client navigates to the pre-active contract workspace and clicks ``Edit Terms''.
      \item The system opens the edit view with current agreement data loaded.
      \item The Client modifies \texttt{terms}, \texttt{expiresAt}, or pre-hold \texttt{totalAmount}.
      \item The Client clicks ``Save Changes''.
      \item The system validates status, hold lock, and milestone deadline bounds before updating the record.
      \item The updated contract is rendered in the workspace.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & The contract is not in \texttt{AWAITING\_PAYMENT} or \texttt{PENDING\_SIGN}, or \texttt{totalAmount} changed after a hold exists. The API returns HTTP 422 (\texttt{ContractNotPendingSignException}).\\ \hline
      A2 & Caller is not the contract owner. The API returns HTTP 403 Forbidden (\texttt{ContractForbiddenException}).\\ \hline
      A3 & New \texttt{expiresAt} precedes one or more milestone due dates. Returns HTTP 422 (\texttt{ContractExpiresAtBeforeMilestonesException}).\\ \hline
      A4 & Database error occurs during update. API returns HTTP 500 (\texttt{FailedToUpdateContractException}).\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contract} & Updated contract entity with recalculated totals and reset signature flags.\\ \hline
      \texttt{updatedAt} & ISO 8601 timestamp reflecting the last modification time.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract terms and milestone records are updated in the database.
      \item \texttt{signedByFreelancer} and \texttt{signedByClient} are reset to \texttt{false}.
      \item Notification dispatched to the Freelancer alerting them of updated contract terms.
\end{itemize}

\Needspace{12\baselineskip}
\subsubsection{ Complete Contract}

\fnhead{Function Trigger}
The Client clicks the ``Complete Contract'' button on an active contract detail workspace once all milestones have been finished and approved.\newline
\textbf{Navigation path:} Client Workspace $\rightarrow$ Contracts $\rightarrow$ Active Contract (\texttt{/\allowbreak{}client/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}slug}) $\rightarrow$ Click ``Complete Contract''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Secondary Actor:} Freelancer (\texttt{FREELANCER} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, PostgreSQL database, and Reviews module.
\end{itemize}

\sublabel{Purpose}
\noindent Concludes the contractual project engagement following settlement of all milestone escrow funds. Completing the contract updates its status to \texttt{COMPLETED} and marks the engagement finalized.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Green-outlined ``Complete Contract'' button displayed in the ``ACTIONS'' section of the right-hand contract status sidebar once all milestones are settled with at least one \texttt{RELEASED} milestone.
      \item Centered confirmation modal dialog displaying the title ``Complete Contract'' and a confirmation message advising that all agreed milestones should be reviewed and approved beforehand.
      \item Action buttons: full-width green pill button ``Mark as Completed'' and secondary ``Cancel'' button.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP request: \texttt{PATCH /\allowbreak{}api/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}id/\allowbreak{}complete}.
      \item \texttt{ContractService.completeContract()} validates that the caller is the contract's Client (\texttt{contract.clientId}).
      \item The service verifies that contract status is currently \texttt{ACTIVE}.
      \item Queries all associated milestones: verifies that every milestone has \texttt{paymentStatus} equal to \texttt{RELEASED} or \texttt{REFUNDED} (\texttt{ContractHasUnsettledMilestonesException} otherwise).
      \item Updates contract status to \texttt{COMPLETED} and sets \texttt{completedAt = new Date()}, and notifies the Freelancer.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ntin/CompleteContract.png}{Complete Contract confirmation screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Behind the modal overlay sits the Contract Agreement workspace showing the contract document and the right-hand Actions sidebar (\texttt{CONTRACT STATUS: Active}, Client and Freelancer signed badges, and ``Complete Contract'').
      \item The centered white modal renders the heading ``Complete Contract'' and prompt ``Are you sure you want to mark this contract as completed? All agreed milestones should be reviewed and approved prior to completion.''
      \item Primary green pill button ``Mark as Completed'' with checkmark icon sits above a full-width ``Cancel'' pill button.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric identifier of the contract to complete (integer path parameter).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The calling user must be the authenticated Client of the contract.
      \item The contract must currently reside in \texttt{ACTIVE} status.
      \item Every milestone must have \texttt{paymentStatus} equal to \texttt{RELEASED} or \texttt{REFUNDED}.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-CT-07: A contract can only transition to \texttt{COMPLETED} when all milestones are settled (\texttt{RELEASED} or \texttt{REFUNDED}).
      \item BR-CT-08: Completed contracts are permanently closed from further deliverable submissions or financial adjustments.
      \item BR-CT-09: Milestone review automation operates on a 7-day timeout (\texttt{CLIENT\_\allowbreak{}REVIEW\_\allowbreak{}TIMEOUT\_\allowbreak{}MS}) for auto-release, while contract completion closes the engagement for both parties.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The Client navigates to the active contract workspace where all milestones are settled.
      \item The Client clicks ``Complete Contract'' in the right-hand Actions sidebar.
      \item The system displays the ``Complete Contract'' confirmation modal.
      \item The Client clicks ``Mark as Completed''.
      \item The system verifies milestone settlement and updates contract status to \texttt{COMPLETED}.
      \item The system sends a completion notification to the Freelancer and transitions the workspace to completed state.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Unapproved or unpaid milestones remain. The API returns HTTP 422 with error \texttt{ContractHasUnreleasedMilestonesException}; displays message indicating pending milestones.\\ \hline
      A2 & An active dispute is currently unresolved. The API returns HTTP 422 with error \texttt{ContractHasActiveDisputeException}; completion blocked.\\ \hline
      A3 & Caller is not the Client owner. The API returns HTTP 403 Forbidden; access denied.\\ \hline
      A4 & Contract is already completed or cancelled. The API returns HTTP 400 Bad Request.\\ \hline
      A5 & Database update failure occurs. System displays: ``Failed to complete contract. Please try again.''\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{status} & Updated contract status (\texttt{COMPLETED}).\\ \hline
      \texttt{completedAt} & ISO 8601 completion timestamp.\\ \hline
      \texttt{reviewWindowExpiresAt} & Timestamp marking review window expiration deadline.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract status is updated to \texttt{COMPLETED} in the database.
      \item Completion notification sent to both Client and Freelancer.
      \item Feedback and review submission prompts are rendered.
\end{itemize}

\Needspace{12\baselineskip}
\subsubsection{ View Contracts List}

\fnhead{Function Trigger}
An authenticated user (Client, Freelancer, or Admin) clicks ``Contracts'' in the dashboard main sidebar navigation.\newline
\textbf{Navigation path:} User Dashboard $\rightarrow$ Navigation Menu $\rightarrow$ Contracts (\texttt{/client/contracts} or \texttt{/freelancer/contracts}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client, Freelancer, Administrator.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Provides a centralized contract management dashboard for users to browse, filter by lifecycle status or proposal, and monitor their freelance contracts (\texttt{AWAITING\_PAYMENT}, \texttt{PENDING\_SIGN}, \texttt{ACTIVE}, \texttt{COMPLETED}, \texttt{DISPUTED}, \texttt{CANCELLED}, \texttt{REJECTED}, \texttt{EXPIRED}).

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contracts dashboard page at \texttt{/client/contracts} or \texttt{/freelancer/contracts}.
      \item Status filter bar supporting contract lifecycle states.
      \item Contract card list rendering job title, counterpart avatar and name, total budget, milestone summary, status badge, and ``View Contract'' link.
      \item Pagination controls footer with page numbers, page size selector, and item summary count.
      \item Empty-state placeholder with helpful guidance when no matching contracts exist.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The web client submits an HTTP request: \texttt{GET /\allowbreak{}api/\allowbreak{}contracts} with query parameters (\texttt{page}, \texttt{limit}, \texttt{status}, \texttt{proposalId}).
      \item The API validates the JWT access token and extracts \texttt{userId} and \texttt{roleName}.
      \item If \texttt{roleName === 'CLIENT'}, queries contracts where \texttt{clientId = userId}; if \texttt{roleName === 'FREELANCER'}, queries contracts where \texttt{freelancerId = userId}; Administrators can query across all contracts.
      \item Applies optional \texttt{status} and \texttt{proposalId} filters.
      \item Computes pagination count in parallel via \texttt{prisma.contract.count()}.
      \item Returns HTTP 200 with contract summaries and pagination metadata.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ntin/ViewContractList.png}{Contracts list dashboard}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The page title ``Contracts'' sits alongside status filter tabs.
      \item Each contract card displays counterpart information, milestone progress, total amount, and ``View Contract'' link.
      \item The pagination component displays current page index, total contracts count, and next/prev controls.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{page} & Page number for paginated retrieval (integer, default 1).\\ \hline
      \texttt{limit} & Number of contracts per page (integer, default 10, max 50).\\ \hline
      \texttt{status} & Optional \texttt{ContractStatus} filter (\texttt{AWAITING\_PAYMENT}, \texttt{PENDING\_SIGN}, \texttt{ACTIVE}, \texttt{COMPLETED}, \texttt{DISPUTED}, \texttt{CANCELLED}, \texttt{REJECTED}, \texttt{EXPIRED}).\\ \hline
      \texttt{proposalId} & Optional positive integer proposal filter.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}

\fnhead{Function Trigger}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]

\end{itemize}

\sublabel{Purpose}
\noindent Captures the digital signature of a contract participant to manifest legal consent to project terms. When both counterparties have signed, the contract advances to platform fee settlement or active state, enabling escrow funding and milestone execution.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item ``Sign Contract'' prominent action button in the contract banner.
      \item Digital signature modal displaying full legal agreement text and milestone schedule.
      \item Mandatory agreement checkbox: ``I have read, understood, and agree to the Frevia Contract Agreement and Terms of Service.''.
      \item Action buttons: ``Confirm \& Digitally Sign'' and ``Review Later''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The user submits an HTTP request: \texttt{PATCH /\allowbreak{}api/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}id/\allowbreak{}sign}.
      \item \texttt{ContractService.signContract()} verifies that the caller is either \texttt{contract.clientId} or \texttt{contract.freelancerId}.
      \item Rejects signing while in \texttt{AWAITING\_PAYMENT} (\texttt{ContractAwaitingPaymentException}); requires status \texttt{PENDING\_SIGN} and non-expired \texttt{expiresAt}.
      \item Enforces sequential signing order: Client must sign first (\texttt{signedByClient = true}); if a Freelancer attempts to sign before the Client, throws \texttt{ClientMustSignFirstException}.

      \item Invokes \texttt{ContractPdfService.generateAndSaveContractPdf()} to generate and store the contract agreement PDF as a \texttt{SharedFile}, and notifies both parties upon activation.
\end{itemize}

      \item The contract must currently reside in \texttt{PENDING\_SIGN} status and not be expired.
      \item Client must sign before the Freelancer, and the Freelancer must have verified Stripe Connect payouts enabled before final activation.

\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist

\end{specdatatable}

\fnhead{Function Trigger}

      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, PostgreSQL database, and Stripe payment refund service.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a contract participant to terminate a pending or active agreement before project completion, voiding pre-capture Stripe holds or executing escrow settlement for active contracts.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Red-outlined ``Cancel Contract'' button in the right-hand Actions sidebar (hidden once all milestones are settled with at least one \texttt{RELEASED} milestone).
      \item Centered ``Cancel Contract'' confirmation modal previewing role-dependent funded escrow settlement (e.g., unstarted milestones refunded to the Client).
      \item Notice advising participants to open a Dispute instead of cancelling if unsatisfied with submitted work.
      \item Action buttons: red pill ``Confirm Cancellation'' and neutral pill ``Go Back''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The user submits an HTTP request without a request body: \texttt{PATCH /\allowbreak{}api/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}id/\allowbreak{}cancel}.
      \item \texttt{ContractService.cancelContract()} validates caller authorization against \texttt{clientId} and \texttt{freelancerId}, rejecting \texttt{CANCELLED}, \texttt{COMPLETED}, or \texttt{DISPUTED} contracts.
      \item If the contract has a pre-capture \texttt{holdPaymentIntentId} and is not \texttt{ACTIVE}, cancels the Stripe pre-authorization hold.
      \item {\sloppy If the contract is \texttt{ACTIVE}, checks that no milestone is \texttt{DISPUTED} and rejects cancellation with \texttt{ContractCannotCancelCompletedMilestonesException} when all milestones are already settled (with at least one \texttt{RELEASED}); otherwise invokes \texttt{PaymentService.\allowbreak{}settleContractEscrowOnCancel(\allowbreak{}contractId, cancelledByRole)}: when Client cancels, funded \texttt{IN\_PROGRESS}/\texttt{CHANGES\_REQUESTED}/\texttt{SUBMITTED} milestones release to Freelancer and unstarted \texttt{PENDING} funded milestones refund to Client; when Freelancer cancels, all funded milestones refund to Client.\par}
      \item Updates contract \texttt{status = CANCELLED} and dispatches an urgent notification to the counterpart party.
\end{itemize}

\screenfigure[0.95]{image/screenshot/sprint1/ntin/CancelContract.png}{Cancel Contract modal}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]

      \item Highlighted summary box breaks down funded escrow settlement by milestone state (e.g., ``Unstarted milestones (refunded to you): \$1,000'').
      \item Helper text advises: ``If you are unsatisfied with the submitted work, please open a Dispute instead of cancelling.''

\end{itemize}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be the Client or Freelancer participant of the contract.
      \item Contract must not already be in \texttt{COMPLETED}, \texttt{CANCELLED}, or \texttt{DISPUTED} status.
      \item Active contracts with any milestone in \texttt{DISPUTED} status cannot be cancelled.
      \item Active contracts whose milestones are all settled (with at least one \texttt{RELEASED}) cannot be cancelled and must be completed instead.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-CT-16: Cancelled contracts cannot be reopened or reactivated under any circumstance.
      \item BR-CT-17: Cancelling an active contract triggers \texttt{settleContractEscrowOnCancel}: Client-initiated cancellation releases funded started milestones to the Freelancer and refunds unstarted funded milestones, whereas Freelancer-initiated cancellation refunds all funded milestones to the Client.
\end{itemize}

\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The user navigates to the contract workspace and selects ``Cancel Contract''.
      \item The system opens the cancellation confirmation dialog.
      \item The user clicks ``Confirm Cancellation''.
      \item The system validates contract and milestone states, settles escrow or cancels pre-auth hold, and updates status to \texttt{CANCELLED}.
      \item Counterpart receives a cancellation notification, and the workspace reflects cancelled state.
\end{enumerate}

\begin{flowtable}{Case}{Description}
      A1 & Contract is already completed or cancelled. The API returns HTTP 422 (\texttt{ContractAlreadyCompletedException} or \texttt{ContractAlreadyCancelledException}).\\ \hline

      A4 & Database update fails. The API returns HTTP 500 (\texttt{FailedToUpdateContractException}).\\ \hline
\end{flowtable}

\end{specdatatable}

\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract status is updated to \texttt{CANCELLED}.
      \item Escrow refunds are initiated for funded unreleased milestones.
      \item Notifications sent to both parties.

      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Multer middleware, Cloudinary cloud object storage, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Enables contract participants to securely upload project assets, deliverables, reference manuals, source files, and documents to the shared contract workspace.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Upload file modal or drag-and-drop zone in the Files tab.
      \item Native file picker dialog supporting multi-format selection.
      \item Progress bar rendering upload percentage and transmission status.
      \item Supported format notice: images (PNG, JPG), documents (PDF, DOCX, XLSX), archives (ZIP, RAR) up to 25MB.
      \item Action buttons: ``Upload'' and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP \texttt{multipart/\allowbreak{}form-\allowbreak{}data} request: \texttt{POST /\allowbreak{}api/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}contractId/\allowbreak{}files} with attached file payload.
      \item \texttt{build\allowbreak{}Upload\allowbreak{}File\allowbreak{}Pipe()} validates file size ($\le$ 25MB) and restricts malicious executable MIME types.
      \item \texttt{Shared\allowbreak{}File\allowbreak{}Service.\allowbreak{}upload\allowbreak{}Shared\allowbreak{}File()} checks participant authorization.
      \item Streams the file buffer to Cloudinary cloud storage under folder \texttt{frevia/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}contractId}.
      \item Persists \texttt{SharedFile} record in database with \texttt{contractId}, \texttt{uploaderId = userId}, \texttt{fileUrl}, \texttt{publicId}, and \texttt{fileName}.
      \item Returns HTTP 201 Created with the saved file record.
\end{itemize}

\fnhead{Function Trigger}

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} File Uploader (Client or Freelancer), Administrator.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Cloudinary cloud storage, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows users to remove obsolete, duplicate, or incorrect files from the contract repository while preserving audit integrity and preventing unauthorized deletion.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Delete trash icon on the file row (conditionally rendered for uploader or Admin).
      \item Confirmation modal: ``Are you sure you want to delete [fileName]? This action cannot be undone.''.
      \item Action buttons: ``Delete'' (destructive red) and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client submits an HTTP request: \texttt{DELETE /\allowbreak{}api/\allowbreak{}contracts/\allowbreak{}:\allowbreak{}contractId/\allowbreak{}files/\allowbreak{}:\allowbreak{}fileId}.
      \item \texttt{SharedFileService.deleteSharedFile()} verifies that the caller is either the file's original \texttt{uploaderId} or possesses \texttt{ADMIN} role.

      \item Initiates asset deletion from Cloudinary cloud storage using \texttt{publicId} when present and soft-deletes the database record (\texttt{deletedAt = new Date()}).
      \item Returns HTTP 200 with deletion confirmation.

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The file must exist within \texttt{contractId} and not already be soft-deleted.
      \item Caller must be the original uploader of the file or an Administrator.
      \item Non-admin uploaders may delete a shared file only within 1 hour of upload creation.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-CT-22: Only the original file uploader or an Administrator shall delete a shared file.
      \item BR-CT-23: Non-admin uploaders can delete a shared file only within the 1-hour expiry window (\texttt{ONE\_HOUR\_MS}); Administrators are exempt from the expiry window.

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]

      \item The system opens the delete confirmation dialog.
      \item The user clicks ``Delete''.
      \item The system validates ownership, checks the 1-hour window for non-admins, deletes the cloud asset when \texttt{publicId} exists, and sets \texttt{deletedAt}.
      \item The dialog closes, the file is removed from the view, and a confirmation toast appears.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}

      \texttt{deletedFileId} & Identifier of the soft-deleted file record.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item File is soft-deleted in the database (\texttt{deletedAt} populated).
      \item File is purged from the shared files view.
\end{itemize}

\subsubsection{ Reject Contract Offer}

\fnhead{Function Trigger}
A Freelancer clicks ``Reject Offer'' upon reviewing an incoming contract offer before signing.\newline
\textbf{Navigation path:} Contract Detail (\texttt{/freelancer/contracts/:slug}) $\rightarrow$ Action Menu $\rightarrow$ Click ``Reject Offer''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Freelancer (\texttt{FREELANCER} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Stripe payment hold service, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a Freelancer to formally decline a pending contract offer. The freelancer provides an optional explanation reason, any Client Stripe authorization hold is automatically voided at zero fee, and the contract transitions to \texttt{REJECTED}.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item ``Reject Offer'' action button on the pending contract detail banner.
      \item Rejection dialog prompting for decline reason and confirmation.
      \item Action triggers: ``Confirm Rejection'' (destructive) and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item The freelancer submits an HTTP request: \texttt{PATCH /api/contracts/:id/reject} with optional \texttt{reason}.
      \item \texttt{ContractService.rejectContract()} verifies caller is the assigned freelancer.
      \item Verifies contract status is \texttt{PENDING\_SIGN} or \texttt{AWAITING\_PAYMENT}.
      \item If \texttt{holdPaymentIntentId} exists, calls Stripe to cancel the pre-authorization hold.
      \item Updates contract \texttt{status = REJECTED}, records \texttt{rejectedAt = now()} and \texttt{rejectReason}.
      \item Triggers notification to the Client alerting them of the declined offer.
\end{itemize}

\screenfigure[0.95]{image/screenshot/sprint1/ntin/RejectContractOffer.png}{Reject Contract Offer confirmation dialog}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Modal displays warning title ``Decline Contract Offer''.
      \item Textarea allows entering explanation for the client (scope, timeline, rate).
      \item Information notice informs that any client deposit authorization will be released.
      \item Footer renders ``Cancel'' and red ``Decline Offer'' buttons.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{reason} & Optional textual explanation for declining the offer (string, up to 500 characters).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be the assigned Freelancer of the contract.
      \item Contract must be in \texttt{PENDING\_SIGN} or \texttt{AWAITING\_PAYMENT} status.
      \item Contract must not have already been signed or accepted by the Freelancer.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-CT-24: Only the assigned Freelancer can reject a pending contract offer.
      \item BR-CT-25: Rejecting a contract immediately voids any active Stripe escrow authorization hold with \$0 fee.
      \item BR-CT-26: A rejected contract offer cannot be reinstated; the Client must create a new contract proposal.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item The Freelancer opens the pending contract offer.
      \item The Freelancer reviews terms and clicks ``Reject Offer''.
      \item The system opens the rejection dialog.
      \item The Freelancer optionally enters a decline reason and confirms.
      \item The backend cancels any pre-authorization hold via Stripe.
      \item The backend updates contract status to \texttt{REJECTED} and records the reason.
      \item The system sends a notification to the Client and updates the workspace.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Caller is not the assigned Freelancer. The API returns HTTP 403 Forbidden.\\ \hline
      A2 & Contract is not in a rejectable status (e.g. already active or cancelled). The API returns HTTP 422 with error \texttt{ContractNotActionableForRejectionException}.\\ \hline
      A3 & Stripe hold cancellation encounters network error. The system logs the incident and proceeds with rejection fallback refund.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{id} & Numeric identifier of the rejected contract.\\ \hline
      \texttt{status} & Updated contract status (\texttt{REJECTED}).\\ \hline
      \texttt{rejectedAt} & ISO 8601 rejection timestamp.\\ \hline
      \texttt{rejectReason} & Recorded explanation text.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Contract status is transitioned to \texttt{REJECTED}.
      \item Stripe pre-authorization hold is voided.
      \item Client is notified with the decline explanation.
\end{itemize}
