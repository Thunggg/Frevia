\subsubsection{Function: View Job List}

\fnhead{Function Trigger}
A guest, freelancer, or client accesses the marketplace job catalog from the navigation menu or search input.\newline
\textbf{Navigation path:} Home $\rightarrow$ Find Work / Browse Jobs (\texttt{/jobs}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Guest, Freelancer, and Client.
    \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia BFF proxy (\texttt{/api/backend}), Frevia REST API (NestJS), and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows any visitor or registered user to browse, search, and filter open freelance job opportunities with pagination, budget constraints, required skills, and keyword matching.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Job browsing page at \texttt{/jobs}.
    \item Search bar and filter sidebar for category, budget range, skill badges, and experience level.
    \item Listing grid of job cards displaying title, description excerpt, client badge, budget, skills, and publication timestamp.
    \item Bottom pagination bar.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item The client issues an HTTP request: \texttt{GET /api/jobs} with query parameters (\texttt{search}, \texttt{categoryId}, \texttt{skills}, \texttt{budgetMin}, \texttt{budgetMax}, \texttt{page}, \texttt{limit}, \texttt{sortBy}).
    \item The backend validates parameters and constructs a Prisma query.
    \item Applies strict constraints: \texttt{status = 'OPEN'}, \texttt{deletedAt = null}, client account is active, and submission deadline is valid.
    \item Returns items alongside pagination metadata (\texttt{totalItems}, \texttt{totalPages}, \texttt{currentPage}).
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ptai/ViewJobList.png}{Job browsing list interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Search bar with keyword input and instant filter execution.
    \item Left sidebar containing filter options (Category, Experience Level, Job Type, Budget Range).
    \item Main area displaying job cards with verified client badges, required skills, and budget values.
    \item Pagination bar showing total results and page navigation.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
\texttt{search} & Optional keyword string to match in job title and description.\\ \hline
\texttt{categoryId} & Optional ID of the job category filter.\\ \hline
\texttt{skills} & Optional list of skill IDs or names to filter.\\ \hline
\texttt{budgetMin} / \texttt{budgetMax} & Optional numeric budget boundaries.\\ \hline
\texttt{page} & Page number, integer $\ge 1$, default 1.\\ \hline
\texttt{limit} & Items per page, integer between 5 and 50, default 10.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \texttt{page} must be an integer $\ge 1$.
    \item \texttt{limit} must be between 1 and 50.
    \item \texttt{budgetMin} must be non-negative and $\le$ \texttt{budgetMax} when both are supplied.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-J04: Draft jobs (\texttt{status = DRAFT}) shall never appear in public search and browsing results.
    \item BR-J25: Closed jobs (\texttt{status = CLOSED}) shall be excluded from the open job listing.
    \item BR-J31: Completed and cancelled jobs shall be omitted from active browsing listings.
    \item BR-J33: Soft-deleted jobs (\texttt{deletedAt !== null}) shall be strictly excluded.
    \item BR-J45: Jobs belonging to suspended or banned clients shall be hidden immediately.
    \item BR-J50: Jobs flagged or suspended by administrative moderation shall be excluded from results.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item The user navigates to \texttt{/jobs}.
    \item Frontend requests \texttt{GET /api/jobs} with query filters.
    \item Backend executes validated Prisma query filtering active \texttt{OPEN} jobs.
    \item Backend returns matching jobs with pagination metadata.
    \item Frontend renders job summary cards and pagination controls.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Invalid query parameters (e.g., negative page number). Backend returns HTTP 400 Bad Request; frontend resets filters to default.\\ \hline
A2 & No jobs match the specified criteria. System returns empty list; frontend displays Empty State with a ``Reset Filters'' button.\\ \hline
A3 & Database connection timeout. Backend returns HTTP 500; frontend displays error message with a ``Retry'' button.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
\texttt{data} & Array of job summary objects (\texttt{id}, \texttt{title}, \texttt{slug}, \texttt{budgetMin}, \texttt{budgetMax}, \texttt{category}, \texttt{skills}, \texttt{client}).\\ \hline
\texttt{meta} & Pagination metadata (\texttt{totalItems}, \texttt{totalPages}, \texttt{currentPage}).\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item The matching job list is rendered for the user.
    \item Search state is reflected in URL search parameters.
\end{itemize}

\subsubsection{Function: View Job Detail}

\fnhead{Function Trigger}
A user clicks on a job card or navigates directly via a job slug URL.\newline
\textbf{Navigation path:} Browse Jobs (\texttt{/jobs}) $\rightarrow$ Click Job Card $\rightarrow$ Job Detail (\texttt{/jobs/:slug}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Guest, Freelancer, and Client.
    \item \textbf{Supporting Systems:} Frevia Web application, Frevia REST API, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Displays complete specifications of a job posting, including comprehensive description, budget type, required skills, attachments, hiring quota, and client hiring history.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Job detail screen at \texttt{/jobs/:slug}.
    \item Action bar with ``Submit Proposal'' button (for Freelancers) or ``Manage Job'' (for Job Owner).
    \item Two-column layout: left column contains full job description and requirements; right column displays client profile, budget summary, and hiring status.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Frontend requests \texttt{GET /api/jobs/:slug}.
    \item Backend checks job visibility: if \texttt{status = 'DRAFT'}, access is restricted to the owning client or administrator.
    \item Increments view counter if viewer is not the owning client.
    \item Returns full job object including client details, category, required skills, and attachments.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ptai/ViewJobDetail.png}{Job detail interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Header displaying job title, category badge, and posting age.
    \item Left content area with detailed project scope, qualifications, and downloadable attachments.
    \item Right sidebar displaying budget, hiring type, deadline, client review rating, and action buttons.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
\texttt{slug} & String identifier in URL representing the job title slug.\\ \hline
Session Token & Optional JWT identifying viewer identity and role.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \texttt{slug} must be non-empty and formatted as a URL-friendly slug.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-J04: Non-owners accessing draft jobs shall receive HTTP 404 Not Found.
    \item BR-J07: The ``Submit Proposal'' button is active only when \texttt{status = 'OPEN'} and hiring quota is not filled.
    \item BR-J37: Displays hiring quota (\texttt{SINGLE} or \texttt{MULTIPLE}) and filled positions.
    \item BR-J42: Job detail is permanently accessible via invariant URL slug.
    \item BR-J49: Explicitly distinguishes between proposal closing date (\texttt{expiryDate}) and project deadline.
    \item BR-J51: Views are incremented only when the viewer is not the job's author.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item User opens \texttt{/jobs/:slug}.
    \item Frontend dispatches \texttt{GET /api/jobs/:slug}.
    \item Backend queries job record with relations (skills, client, attachments).
    \item Backend returns detailed job object.
    \item Frontend renders full view and enables actions according to user role and job state.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Slug does not exist or job is soft-deleted. Backend returns HTTP 404; frontend redirects to 404 page.\\ \hline
A2 & Job is in DRAFT and viewer is not the client owner. Backend returns HTTP 403 Forbidden; frontend shows access denied notice.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
Job Object & Complete entity containing \texttt{id}, \texttt{title}, \texttt{description}, \texttt{budgetType}, \texttt{budgetMin}, \texttt{budgetMax}, \texttt{hiringType}, \texttt{positionsRequired}, \texttt{positionsFilled}, \texttt{skills}, \texttt{attachments}, and \texttt{client}.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Full job specifications are displayed.
    \item Proposal action is enabled if user is an eligible freelancer.
\end{itemize}

\subsubsection{Function: View My Jobs}

\fnhead{Function Trigger}
A client clicks on ``My Jobs'' in the main navigation.\newline
\textbf{Navigation path:} Home $\rightarrow$ Client Dashboard $\rightarrow$ My Jobs (\texttt{/client/jobs}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Client.
    \item \textbf{Supporting Systems:} Frevia Web application, Frevia REST API, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Provides clients with an overview of all jobs they have created across all lifecycle stages (\texttt{DRAFT}, \texttt{OPEN}, \texttt{IN\_PROGRESS}, \texttt{CLOSED}, \texttt{COMPLETED}), showing proposal counts and management shortcuts.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Client jobs management table at \texttt{/client/jobs}.
    \item Status tab bar: All, Open, Drafts, In Progress, Closed.
    \item Row action dropdowns (Edit, Close, Reopen, Delete, Review Proposals).
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Client requests \texttt{GET /api/client/jobs}.
    \item Backend extracts client ID from JWT token to prevent unauthorized access (IDOR guard).
    \item Filters by \texttt{clientId} and excludes soft-deleted items.
    \item Returns list sorted by creation date descending with aggregate proposal counts.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ptai/ViewMyJobs.png}{Client My Jobs interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Tab bar filtering jobs by operational status.
    \item Table listing jobs with title, budget, proposal counter badge, and date posted.
    \item Action menu on each row for editing, closing, or viewing submitted proposals.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
JWT Token & Authenticated client token containing user ID and active Client role.\\ \hline
\texttt{status} & Optional query string filter (\texttt{ALL}, \texttt{DRAFT}, \texttt{OPEN}, \texttt{CLOSED}).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item User must possess the \texttt{CLIENT} role.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-J01: Only accounts with \texttt{CLIENT} role may access this screen.
    \item BR-J14: Query is strictly scoped to \texttt{job.clientId === currentUserId}.
    \item BR-J33: Soft-deleted jobs are excluded from the default view.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item Client visits \texttt{/client/jobs}.
    \item Client application requests \texttt{GET /api/client/jobs}.
    \item Backend validates client session and fetches own job listings.
    \item UI renders table with status tags and management actions.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Unauthenticated or non-client role. Backend returns HTTP 403; redirected to login/onboarding.\\ \hline
A2 & No jobs created yet. UI shows empty state with ``Post a Job'' call to action.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
\texttt{jobs} & Array of jobs with fields \texttt{id}, \texttt{title}, \texttt{status}, \texttt{budgetMin}, \texttt{budgetMax}, \texttt{proposalCount}, and \texttt{createdAt}.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Client views complete job portfolio and proposal counts.
\end{itemize}

\subsubsection{Function: Create Job}

\fnhead{Function Trigger}
A client clicks ``Post a Job'' from the client workspace.\newline
\textbf{Navigation path:} Client Dashboard $\rightarrow$ Click ``Post a Job'' (\texttt{/client/jobs/new}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Client.
    \item \textbf{Supporting Systems:} Frevia Web application, Frevia REST API, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows a client to create a new job posting in \texttt{DRAFT} status with specifications including title, category, skills, budget range, hiring type, and file attachments.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Multi-step job posting form at \texttt{/client/jobs/new}.
    \item Title and description inputs with rich text support.
    \item Category selector, skill tag autocomplete, and budget input fields.
    \item Attachment uploader supporting up to 5 files.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Client submits form payload via \texttt{POST /api/client/jobs}.
    \item Backend validates required fields, budget values, and category status.
    \item Generates a unique invariant slug from title.
    \item Persists job record with initial state \texttt{status = 'DRAFT'}.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ptai/CreateJob.png}{Post a new job form}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Step indicator showing form progression.
    \item Form fields for title, category dropdown, skill tagging, budget bounds, and description.
    \item Action buttons for ``Save as Draft'' and ``Continue to Review''.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
\texttt{title} & String (10--100 characters), job headline.\\ \hline
\texttt{categoryId} & UUID of the selected job category.\\ \hline
\texttt{skillIds} & Array of skill UUIDs (1 to 10 skills).\\ \hline
\texttt{budgetType} & Enum: \texttt{FIXED\_PRICE} or \texttt{HOURLY}.\\ \hline
\texttt{budgetMin} / \texttt{budgetMax} & Numeric values representing compensation bounds.\\ \hline
\texttt{hiringType} & Enum: \texttt{SINGLE} or \texttt{MULTIPLE}.\\ \hline
\texttt{description} & Detailed job description text.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Title must be between 10 and 100 characters.
    \item Category must be active and valid.
    \item Must specify between 1 and 10 skills.
    \item Budget minimum must be $\ge 10$ USD and $\le$ budget maximum.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-J01: Only clients may create jobs.
    \item BR-J02: Newly created jobs are always initialized with \texttt{status = DRAFT}.
    \item BR-J37: Defaults to \texttt{SINGLE} hiring type with \texttt{positions\_required = 1}.
    \item BR-J41: Enforces minimum budget of \$10 for fixed-price contracts.
    \item BR-J42: Automatically generates invariant slug upon creation.
    \item BR-J50: Scans for prohibited direct contact information (phone, external URLs).
    \item BR-J52: Exactly one category must be selected.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item Client fills out the job creation form.
    \item Client clicks ``Save as Draft''.
    \item Frontend sends payload to \texttt{POST /api/client/jobs}.
    \item Backend validates inputs, generates slug, and saves record as \texttt{DRAFT}.
    \item Backend returns created job entity; client is redirected to draft review page.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Validation error (e.g., title too short or invalid budget). Returns HTTP 400 with field errors; highlights invalid inputs.\\ \hline
A2 & Client account restricted from posting. Returns HTTP 403; displays account verification requirement.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
Job Record & Created entity with \texttt{id}, \texttt{slug}, \texttt{status = DRAFT}, and timestamps.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item A new job record is created in \texttt{DRAFT} state.
\end{itemize}

\subsubsection{Function: Publish Job}

\fnhead{Function Trigger}
A client clicks ``Publish Job'' on a draft job posting.\newline
\textbf{Navigation path:} Client Dashboard $\rightarrow$ My Jobs $\rightarrow$ Draft Job $\rightarrow$ Click ``Publish Job''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Client.
    \item \textbf{Supporting Systems:} Frevia Web application, Frevia REST API, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Validates completeness of a draft job, transitions its status to \texttt{OPEN}, indexes it in search, and activates public proposal submission.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Draft job review screen with a prominent ``Publish Job'' button.
    \item Confirmation modal explaining that key terms become permanent upon publishing.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Client submits \texttt{POST /api/client/jobs/:id/publish}.
    \item Backend verifies that all mandatory fields are present and valid.
    \item Verifies ownership (\texttt{job.clientId === currentUserId}).
    \item Updates \texttt{status = 'OPEN'}, sets \texttt{publishedAt = now()}, and triggers job alert events.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint1/ptai/PublishJob.png}{Publish job confirmation screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Summary card detailing the final parameters of the job.
    \item Checklist showing that title, category, skills, and budget are fully configured.
    \item Primary ``Confirm \& Publish Now'' action button.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
\texttt{id} & UUID of the draft job to publish.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Target job must currently be in \texttt{DRAFT} status.
    \item All required fields (title, category, $\ge 1$ skill, budget, description) must be populated.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-J05: Only jobs with complete, valid specifications can be published.
    \item BR-J06: Publishing transitions state from \texttt{DRAFT} to \texttt{OPEN} and sets \texttt{publishedAt}.
    \item BR-J14: Client must own the job posting.
    \item BR-J41: Currency and budget type become immutable upon publishing.
    \item BR-J42: URL slug is permanently frozen after publishing.
    \item BR-J51: Triggers matching job alerts (UC-23) to notify relevant freelancers.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item Client reviews draft job and clicks ``Publish Job''.
    \item System verifies completeness and ownership.
    \item System updates job status to \texttt{OPEN}.
    \item System indexes job in search and queues job alert notifications.
    \item UI redirects to active job page with a success toast notification.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
A1 & Missing required fields. Backend returns HTTP 422 Unprocessable Entity with list of incomplete fields.\\ \hline
A2 & Job is not in DRAFT status. Backend returns HTTP 400 Bad Request.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
Updated Job & Job object with \texttt{status = OPEN} and populated \texttt{publishedAt}.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Job is public and accepting proposals.
\end{itemize}

\subsubsection{Function: Update Job}

\fnhead{Function Trigger}
A client clicks ``Edit'' on an active or draft job.\newline
\textbf{Navigation path:} Client Dashboard $\rightarrow$ My Jobs $\rightarrow$ Click ``Edit'' (\texttt{/client/jobs/:id/edit}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} Client.
    \item \textbf{Supporting Systems:} Frevia Web application, Frevia REST API, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows clients to revise job parameters, requirements, and descriptions according to lifecycle editing rules.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Job editing form pre-filled with existing data.
    \item Locked fields indicator for published jobs (budget type, category, and slug).
