\subsection{Freelancer Profile Management}
\Needspace{10\baselineskip}
\subsubsection{Function: View Freelancer Profile (UC-07.01)}
\label{fn:nhuy-uc-07-01}

\Needspace{7\baselineskip}
\fnhead{Function Trigger}
The actor selects View Freelancer Profile. Navigation: /freelancer/profile; /profiles/[id].

\Needspace{7\baselineskip}
\fnhead{Function Description}
\Needspace{5\baselineskip}
\sublabel{Actors / Roles}
Guest, Client, Freelancer.
\Needspace{5\baselineskip}
\sublabel{Purpose}
Retrieve approved Profile and FreelancerProfile fields in one response.
\Needspace{5\baselineskip}
\sublabel{Interface and Data Processing}
{\small\texttt{GET /\allowbreak{}profiles/\allowbreak{}:id}}. The browser calls the Next.js BFF, which forwards authenticated requests to the NestJS API. The server derives the acting user from authentication and accesses Profile, FreelancerProfile, ProfileRevision. Route IDs are validated independently from owner IDs.

\Needspace{7\baselineskip}
\fnhead{Screen Layout (Mock-up Description)}
\begin{center}
\fbox{\begin{minipage}{0.88\linewidth}
\textbf{View Freelancer Profile}\par\smallskip
Profile header with name and availability; professional sections; Skills and Portfolio panels; owner-only Edit and CV controls.\par\smallskip
\textit{Schematic interface description, not an application screenshot.}
\end{minipage}}
\end{center}

\Needspace{7\baselineskip}
\Needspace{18\baselineskip}
\fnhead{Function Details}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Input Data}
\begin{specdatatable}{Data}{Definition}
Identifier & Positive resource ID from the route; ownership is checked by the API. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Validation and Business Rules}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Use Profile.id for profile routes; User.id identifies the owner and must not be substituted for the profile ID.
\item Only the owner changes professional data. Public output excludes credentials and private CV locations.
\item Omitted optional fields are preserved. An explicit null or empty list clears the corresponding value.
\item Freelancer and Client updates below 20 percent profile strength require a pending revision; other updates apply directly. Pending changes are not shown as approved public data.
\end{itemize}
\Needspace{5\baselineskip}
\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item The actor opens /freelancer/profile; /profiles/[id] and selects View Freelancer Profile.
\item The application submits the selected identifier or list filters.
\item The API checks authentication where required, authorization, resource existence and input validity.
\item Retrieve approved Profile and FreelancerProfile fields in one response.
\item The screen renders the response, or an explicit empty state for a valid empty collection.
\end{enumerate}
\Needspace{5\baselineskip}
\sublabel{Alternative Flow}
Show an informative empty state for a valid empty result and allow retry after a transport failure.
\Needspace{5\baselineskip}
\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
E1 & Missing or expired authentication, or insufficient role/ownership: deny the operation and do not change data. \\ \hline
E2 & Missing, deleted or inaccessible resource: show a not-found result. \\ \hline
A1 & A valid empty collection displays an empty state; it must not be treated as a missing account. \\ \hline
E4 & Database, network or storage failure: report a retryable error; do not report success or terminate the API process. \\ \hline
\end{flowtable}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Output Data}
\begin{specdatatable}{Data}{Definition}
Result & Retrieve approved Profile and FreelancerProfile fields in one response. \\ \hline
Failure & Structured error without sensitive data; no successful UI state when the operation failed. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Acceptance Criteria}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Successful view freelancer profile produces the documented response and survives a reload where data is persisted.
\item An unauthorized actor cannot access or modify the resource.
\item Invalid input and missing resources do not create a false success state or expose sensitive data.
\end{itemize}
