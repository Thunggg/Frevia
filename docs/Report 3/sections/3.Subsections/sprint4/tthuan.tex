\subsubsection{Function: View Banner List}

\fnhead{Function Trigger}
An administrator navigates to the Banners management page from the admin dashboard sidebar navigation.\newline
\textbf{Navigation path:} Admin Dashboard $\rightarrow$ Marketing \& Banners $\rightarrow$ Banners (\texttt{/admin/banners}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} System Administrator (\texttt{ADMIN} role).
    \item \textbf{Supporting Systems:} Frevia Web management console (Next.js), Frevia REST API service (NestJS), Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows administrators to view, search, filter, and sort all promotional and advertisement banners registered in the system. The catalog displays essential banner attributes including ID, title, target position slot, publication schedule, active status, thumbnail preview, and destination URL.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Banner management screen at \texttt{/admin/banners}.
    \item Filter bar component (\texttt{BannersFilterBar}) containing search input, position slot dropdown, sort column selector, and sort direction toggle.
    \item Data table component (\texttt{BannersTable}) rendering banner rows, thumbnail image previews, position badges, active status toggles, schedule ranges, and contextual action menus.
    \item Standard pagination footer displaying total banners and page navigation controls.
    \item ``Create Banner'' action button in the page header.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item The client initiates an HTTP request: \texttt{GET /api/admin/banners} with query parameters (\texttt{page}, \texttt{limit}, \texttt{search}, \texttt{position}, \texttt{sortBy}, \texttt{sortOrder}).
    \item The backend \texttt{AuthGuard} validates the administrator's JWT access token, and \texttt{PermissionGuard} verifies administrative route authorization.
    \item \texttt{BannersAdminController.listBanners()} parses query parameters via \texttt{BannerAdminQueryDto}.
    \item \texttt{BannersAdminRepository.listBanners()} executes \texttt{prisma.advertisementBanner.findMany} with:
        \begin{itemize}[leftmargin=1.6em,topsep=2pt,itemsep=2pt,parsep=0pt]
            \item Substring search on \texttt{title} using case-insensitive mode if \texttt{search} is provided.
            \item Exact filter on \texttt{position} if a specific position slot is selected.
            \item Sorting on the requested field (\texttt{id} or \texttt{createdAt}) with specified order (\texttt{asc} or \texttt{desc}).
        \end{itemize}
    \item The repository executes \texttt{prisma.advertisementBanner.count()} in parallel to obtain total matching records.
    \item The system returns HTTP 200 with the banners array and pagination metadata.
    \item The frontend renders the data table, applies position badge styling, and displays schedule ranges.
\end{itemize}

\screenfigure[0.95]{image/screenshot/sprint4/tthuan/ViewBannerList.png}{Advertisement banner list interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Page header displaying ``Banners'' title with megaphone icon, summary count, and ``Create Banner'' button.
    \item Filter bar including search box, position dropdown selector (All Positions, Global Header, Home Hero, Home Body, Search Results, Footer), and sort order controls.
    \item Table columns: \textbf{Banner} (Thumbnail, Title, and ID), \textbf{Position} (Colored badge), \textbf{Status} (Green ``Active'' or Gray ``Inactive''), \textbf{Schedule} (Start date to End date), \textbf{Destination Link}, and \textbf{Actions}.
    \item Row-level action buttons providing quick access to view detail, edit, and delete banner.
    \item Pagination footer indicating total count and page navigation buttons.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
page & Target page number (defaults to 1).\\ \hline
limit & Maximum records returned per page (defaults to 10).\\ \hline
search & Optional text query matching banner title.\\ \hline
position & Optional position filter (\texttt{GLOBAL\_HEADER}, \texttt{HOME\_HERO}, \texttt{HOME\_BODY}, \texttt{SEARCH\_RESULTS}, \texttt{FOOTER}).\\ \hline
sortBy & Sort column field (\texttt{id} or \texttt{createdAt}; defaults to \texttt{id}).\\ \hline
sortOrder & Sort direction sequence (\texttt{asc} or \texttt{desc}; defaults to \texttt{desc}).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{specdatatable}{Data Name}{Validation Rule}
page & Must be an integer greater than or equal to 1.\\ \hline
limit & Must be an integer between 1 and 100.\\ \hline
search & String, optional, max length 100 characters; whitespace trimmed.\\ \hline
position & Optional string, must strictly match one of the defined \texttt{BannerPositionEnum} values.\\ \hline
sortBy & Must strictly be one of: \texttt{id}, \texttt{createdAt}.\\ \hline
sortOrder & Must strictly be one of: \texttt{asc}, \texttt{desc}.\\ \hline
\end{specdatatable}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-BAN-01: Admin Permission Verification: Only authenticated users with role \texttt{ADMIN} and matching route permission can query the administrative banner catalog.
    \item BR-BAN-02: Search and Position Filter Matching: Text search performs case-insensitive substring matching on \texttt{title}, while position filtering performs exact equality matching.
    \item BR-BAN-03: Default Pagination and Ordering: Default page size is 10 records, ordered by \texttt{id} in descending order so newly created banners appear first.
    \item BR-BAN-04: Active and Schedule Range Representation: Displays visual badges for active/inactive state along with formatted publication date intervals (\texttt{startDate} to \texttt{endDate}).
    \item BR-BAN-05: Direct Detail and Modification Actions: Each table row provides direct triggers to view detail, open update form modal, or initiate hard deletion.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item The administrator opens the \texttt{/admin/banners} page from the admin dashboard.
    \item The client issues \texttt{GET /api/admin/banners} with query parameters (\texttt{page=1\&limit=10\&sortBy=id\&sortOrder=desc}).
    \item The backend validates administrative authentication and route permissions.
    \item The repository queries advertisement banners and counts total matching records.
    \item The backend returns HTTP 200 with the banners array and pagination metadata.
    \item The frontend renders the banner table and pagination controls.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Abnormal Case}{Handling \& System Response}
Missing or invalid authentication token & The server returns HTTP 401 Unauthorized. The client clears authentication cookies and redirects to \texttt{/login}.\\ \hline
User lacks Admin privileges & The backend throws HTTP 403 Forbidden. The UI displays: ``You do not have permission to access this page.''\\ \hline
Invalid pagination parameter values & The DTO validator rejects non-integer or negative values with HTTP 400 Bad Request. The client resets to page 1.\\ \hline
Invalid position filter parameter & The validator rejects unknown position strings with HTTP 400 Bad Request. The UI clears invalid position filter.\\ \hline
Unsupported sort column parameter & The validator rejects invalid sort keys with HTTP 400 Bad Request. The client defaults to sorting by \texttt{id desc}.\\ \hline
Database query error or timeout & The service catches the Prisma error and throws \texttt{FailedToLoadBannerListException} (HTTP 500). The UI displays: ``Error.FailedToLoadBanners''.\\ \hline
No banners match search or position filter & The query returns \texttt{banners: []} and \texttt{total: 0}. The table displays an empty placeholder: ``No banners found.''\\ \hline
Network connection failure & The client displays a connection failure toast notification and offers a ``Try again'' button.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Output Field}{Description}
banners & Array of banner objects: \texttt{id}, \texttt{title}, \texttt{imageUrl}, \texttt{linkUrl}, \texttt{position}, \texttt{startDate}, \texttt{endDate}, \texttt{isActive}, \texttt{createdAt}, \texttt{updatedAt}.\\ \hline
pagination.page & Current page number.\\ \hline
pagination.limit & Current limit per page.\\ \hline
pagination.total & Total advertisement banners matching the query.\\ \hline
pagination.totalPages & Total calculated pages available.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\noindent The administrator views the paginated list of advertisement banners, inspects status and positions, and can initiate creation, inspection, modification, or deletion actions.

    \item The frontend renders the banner details layout, full image preview, and action controls.
\end{itemize}

\subsubsection{Function: Create Banner}

\fnhead{Function Trigger}
An administrator clicks the ``Create Banner'' button on the banner list page (\texttt{/admin/banners}), opening the banner creation dialog modal.\newline
\textbf{Navigation path:} Admin Dashboard $\rightarrow$ Marketing \& Banners $\rightarrow$ Banners $\rightarrow$ [Create Banner Button].

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} System Administrator (\texttt{ADMIN} role).
    \item \textbf{Supporting Systems:} Frevia Web management console (Next.js), Frevia REST API service (NestJS), Cloudinary media storage service, Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows administrators to register a new advertisement banner, specifying title, position slot, optional graphic image upload, target redirect link, publication date range, and initial active status.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Banner form dialog modal (\texttt{BannerFormDialog}).
    \item Text input for Title (mandatory).
    \item Dropdown selector for Position slot (\texttt{GLOBAL\_HEADER}, \texttt{HOME\_HERO}, \texttt{HOME\_BODY}, \texttt{SEARCH\_RESULTS}, \texttt{FOOTER}).
    \item File upload input with preview for banner image (supports drag-and-drop or file browser, max 10MB).
    \item Text input for Destination Link URL.
    \item Date picker inputs for Start Date and End Date.
    \item Checkbox toggle for ``Active'' status (defaults to checked).
    \item ``Cancel'' and ``Create Banner'' submission buttons with loading indicator.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item If a local image file is chosen, the client first issues a multipart/form-data request: \texttt{POST /api/admin/banners/upload-image}.
        \begin{itemize}[leftmargin=1.6em,topsep=2pt,itemsep=2pt,parsep=0pt]
            \item The service validates file presence, MIME type (\texttt{image/jpeg}, \texttt{image/png}, \texttt{image/gif}, \texttt{image/webp}, \texttt{image/bmp}, \texttt{image/tiff}), and file size ($\le 10$MB).
            \item If Cloudinary is configured, uploads file to Cloudinary under folder \texttt{frevia/banners} and obtains \texttt{secure\_url}; otherwise saves file to local directory \texttt{uploads/banners/}.
            \item Returns \texttt{\{ imageUrl, publicId \}}.
        \end{itemize}
    \item The client issues an HTTP request: \texttt{POST /api/admin/banners} with JSON payload conforming to \texttt{BannerCreateBodySchema}.
    \item \texttt{BannersAdminRepository.createBanner()} checks whether an active banner already occupies the selected position slot (\texttt{prisma.advertisementBanner.findFirst({ where: { position } })}).
    \item If position is already occupied, the service throws \texttt{BannerPositionTakenException} (HTTP 409).
    \item The repository inserts the new banner record via \texttt{prisma.advertisementBanner.create()}.
    \item The backend returns HTTP 201 with the created banner entity.
    \item The frontend shows a success toast notification, closes the dialog modal, and refreshes the banner list table.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint4/tthuan/CreateBanner.png}{Create banner modal interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Dialog header with ``Create Banner'' title and brief descriptive subtitle.
    \item Form fields: \textbf{Title} (Required text input), \textbf{Position} (Select dropdown: Global Header, Home Hero, Home Body, Search Results, Footer), \textbf{Banner Image} (Upload zone with image preview and remove button), \textbf{Destination Link} (URL input), \textbf{Schedule} (Start Date and End Date date pickers), and \textbf{Active} (Checkbox toggle).
    \item Dialog footer with ``Cancel'' button and ``Create Banner'' submit button with loading spinner.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
title & Banner title string (mandatory).\\ \hline
imageUrl & Direct image URL string or uploaded file URL (optional).\\ \hline
file & Binary image file for upload (optional, multipart/form-data).\\ \hline
linkUrl & Target destination URL string (optional).\\ \hline
position & Target display position slot enum (defaults to \texttt{GLOBAL\_HEADER}).\\ \hline
startDate & Scheduled start publication date (optional).\\ \hline
endDate & Scheduled end publication date (optional).\\ \hline
isActive & Boolean activation flag (defaults to \texttt{true}).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{specdatatable}{Data Name}{Validation Rule}
title & String, trimmed, min 1 char (\texttt{Error.BannerTitleRequired}), max 255 chars (\texttt{Error.BannerTitleTooLong}).\\ \hline
imageUrl & Optional string, must be valid URL format, max 500 chars (\texttt{Error.BannerImageUrlTooLong}).\\ \hline
file & Must be valid image MIME type; size must not exceed 10MB (\texttt{Error.BannerImageTooLarge}).\\ \hline
linkUrl & Optional string, must be valid URL format, max 500 chars (\texttt{Error.BannerLinkUrlTooLong}).\\ \hline
position & Must match one of \texttt{BannerPositionEnum} values (defaults to \texttt{GLOBAL\_HEADER}).\\ \hline
startDate, endDate & Coerced to valid Date. Refinement: if both present, \texttt{startDate <= endDate} (\texttt{Error.BannerInvalidDateRange}).\\ \hline
isActive & Boolean value (defaults to \texttt{true}).\\ \hline
\end{specdatatable}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
    \item BR-BAN-10: Single Active Banner Per Position: Each position slot can only be occupied by one banner; if the position is already taken, creation is rejected with HTTP 409 (\texttt{Error.BannerPositionTaken}).
    \item BR-BAN-11: Mandatory Title Trimming: Title is mandatory and leading/trailing whitespace is stripped before validation and database persistence.
    \item BR-BAN-12: Target and Image URL Validation: If provided, URLs must be strictly valid URI formats with a maximum length of 500 characters.
    \item BR-BAN-13: Valid Schedule Range: When both dates are specified, \texttt{startDate} must be earlier than or equal to \texttt{endDate}.
    \item BR-BAN-14: Image Upload Constraints: Image uploads are strictly limited to valid image MIME formats and maximum size of 10MB.
    \item BR-BAN-15: Auto-refresh and Feedback: Shows a success toast notification and refreshes the banner catalog upon successful creation.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt]
    \item The administrator clicks ``Create Banner'' on the banner management page.
    \item The dialog modal opens with an empty form and default position (\texttt{GLOBAL\_HEADER}).
    \item The administrator fills in the title, selects a position slot, optionally attaches an image file, enters a link URL, selects date bounds, and checks ``Active''.
    \item If a file was attached, the client uploads it to \texttt{POST /api/admin/banners/upload-image} and receives the image URL.
    \item The client submits the form data via \texttt{POST /api/admin/banners}.
    \item The backend validates the payload and verifies the position slot is available.
    \item The repository inserts the new banner record into the database.
    \item The backend returns HTTP 201 with the created banner data.
    \item The frontend closes the modal, displays a success toast, and refreshes the banner list.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Abnormal Case}{Handling \& System Response}
Missing mandatory title & The form prevents submission; backend returns HTTP 400 Bad Request with \texttt{Error.BannerTitleRequired}.\\ \hline
Selected position already occupied & The service throws \texttt{BannerPositionTakenException} (HTTP 409 Conflict). The UI displays: ``Error.BannerPositionTaken''.\\ \hline
Uploaded file exceeds 10MB & The upload endpoint throws \texttt{BannerImageTooLargeException} (HTTP 400). The UI displays: ``Error.BannerImageTooLarge''.\\ \hline
Uploaded file is not a supported image format & The upload endpoint throws \texttt{BannerImageInvalidTypeException} (HTTP 400). The UI displays: ``Error.BannerImageInvalidType''.\\ \hline
End date is earlier than start date & Zod refinement rejects payload with HTTP 400 Bad Request (\texttt{Error.BannerInvalidDateRange}). The UI flags the End Date field.\\ \hline
Invalid URL syntax in image or link URL & Validator returns HTTP 400 Bad Request. The UI highlights the offending URL input field.\\ \hline
Unauthorized or unauthenticated request & The server returns HTTP 401/403. The UI redirects to login or displays an access denied message.\\ \hline
Database insert failure & The service throws \texttt{FailedToCreateBannerException} (HTTP 500). The UI displays: ``Error.FailedToCreateBanner''.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Output Field}{Description}
id & Auto-generated unique identifier of the created banner.\\ \hline
title & Stored banner title string.\\ \hline
imageUrl & Image asset URL or null.\\ \hline
linkUrl & Destination URL or null.\\ \hline
position & Assigned position slot enum.\\ \hline
startDate & Activation date or null.\\ \hline
endDate & Deactivation date or null.\\ \hline
isActive & Active boolean status.\\ \hline
createdAt & Timestamp of creation.\\ \hline
updatedAt & Timestamp of last update.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\noindent A new advertisement banner is stored in the database, assigned to the selected position slot, and immediately rendered on the admin table.

\subsubsection{Function: Update Banner}

\fnhead{Function Trigger}
An administrator clicks the Edit icon in the banner table row or the ``Edit Banner'' button on the banner detail page, opening the edit dialog modal.\newline
\textbf{Navigation path:} Admin Dashboard $\rightarrow$ Marketing \& Banners $\rightarrow$ Banners $\rightarrow$ [Edit Action Button].

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item \textbf{Primary Actor:} System Administrator (\texttt{ADMIN} role).
    \item \textbf{Supporting Systems:} Frevia Web management console (Next.js), Frevia REST API service (NestJS), Cloudinary media storage service, Prisma ORM layer, and PostgreSQL relational database.
\end{itemize}

\sublabel{Purpose}
\noindent Allows administrators to modify an existing advertisement banner's title, display position, image graphic, destination link, validity period, and active status.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item Banner form dialog modal (\texttt{BannerFormDialog}) pre-populated with existing banner data.
    \item Text input for Title.
    \item Select dropdown for Position slot.
    \item File upload input with current image preview and remove button.
    \item Text input for Destination Link URL.
    \item Date pickers for Start Date and End Date.
    \item Checkbox toggle for ``Active'' status.
    \item ``Cancel'' and ``Save Changes'' action buttons.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
    \item The client pre-fills the form with existing banner fields.
    \item If a new replacement image is selected, the client uploads it via \texttt{POST /api/admin/banners/upload-image} before submitting changes.
    \item The client issues an HTTP request: \texttt{PATCH /api/admin/banners/:id} with updated attributes.
    \item \texttt{BannersAdminRepository.updateBanner(id, data)}:
        \begin{itemize}[leftmargin=1.6em,topsep=2pt,itemsep=2pt,parsep=0pt]
            \item Verifies target banner exists; throws \texttt{BannerAdminNotFoundException} if not found.
            \item If \texttt{position} is changed, checks if another banner already occupies the new position slot (\texttt{id != currentId}). Throws \texttt{BannerPositionTakenException} if taken.

    \item The frontend displays a success toast, closes the modal, and refreshes the skill table.

Database update failure & The service throws \texttt{FailedToRestoreSkillException} (HTTP 500). The UI displays: ``Error.FailedToRestoreSkill''.\\ \hline
Network failure during request & The client catches the network error, displays an unexpected error toast, and preserves dialog state.\\ \hline
\end{flowtable}

\end{specdatatable}

\sublabel{Post-Conditions}
\noindent The skill is restored to active status (\texttt{deletedAt = null}), displayed in the active skill catalog, and available for selection in freelancer profiles and job postings.
