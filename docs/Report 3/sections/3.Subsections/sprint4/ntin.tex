\subsubsection{ Connect Stripe Account}

\fnhead{Function Trigger}
A Freelancer clicks ``Set up Payouts'' or ``Connect Stripe'' in their Billing and Payout Settings.\newline
\textbf{Navigation path:} Freelancer Dashboard $\rightarrow$ Settings $\rightarrow$ Payout Settings (\texttt{/freelancer/settings/payouts}) $\rightarrow$ Click ``Connect with Stripe''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Freelancer (\texttt{FREELANCER} role).
      \item \textbf{Secondary Actor:} Stripe Connect Service.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Stripe API SDK, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Enables a Freelancer to link their bank account or debit card via Stripe Connect Express onboarding. Establishing this connection is required to receive automated escrow disbursements, milestone earnings payouts, and dispute resolution settlement funds.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Payout Settings screen at \texttt{/freelancer/settings/payouts}.
      \item Status banner indicating connection state: ``Unconnected'', ``Action Required'', or ``Connected \& Verified''.
      \item Primary action button: ``Connect with Stripe'' or ``Update Payout Details''.
      \item Stripe-hosted Express onboarding flow for identity verification, tax details, and bank account entry.
      \item Return confirmation banner upon redirect back to Frevia.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Freelancer submits an HTTP request: \texttt{POST /api/payments/connect/onboarding-link} with optional \texttt{returnUrl}.
      \item \texttt{PaymentService.getOnboardingLink()} validates caller identity and role.
      \item If no Stripe Account ID exists for the user, creates a new Stripe Express account via \texttt{stripe.accounts.create()} and stores \texttt{stripeAccountId} in the database.
      \item Generates a single-use onboarding URL via \texttt{stripe.accountLinks.create()} with refresh and return routes.
      \item Freelancer completes onboarding on Stripe-hosted UI and is redirected back to Frevia.
      \item Client queries \texttt{GET /api/payments/connect/status} which synchronizes \texttt{chargesEnabled}, \texttt{payoutsEnabled}, and \texttt{detailsSubmitted}.
      \item Returns HTTP 200 with connection status flags.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint4/ntin/ConnectStripeAccount.png}{Stripe Connect payout settings screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Header renders title ``Payout Settings'' and a description of secure bank transfers powered by Stripe.
      \item A prominent card displays the Stripe logo, current status badge (e.g., green ``Verified''), and bank account snippet.
      \item If unlinked, a prominent purple ``Set Up Stripe Express Payouts'' button is centered with security badges.
      \item A secondary link allows managing tax documents or changing payout schedules directly in Stripe.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{returnUrl} & Optional callback URL to return after onboarding (string, URL format).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be an authenticated Freelancer.
      \item User account must have status \texttt{ACTIVE}.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-PAY-01: Freelancers must have a verified Stripe account with payouts enabled to receive contract payments.
      \item BR-PAY-02: Banking credentials and tax identifiers are stored exclusively by Stripe; Frevia stores only the account reference ID.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Freelancer navigates to Payout Settings and clicks ``Connect with Stripe''.
      \item API creates or retrieves Stripe Express account and generates onboarding link.
      \item Browser redirects to Stripe-hosted verification flow.
      \item Freelancer completes banking and identity verification.
      \item Stripe redirects back to Frevia return URL.
      \item System synchronizes account status, updates \texttt{stripeOnboardingCompleted = true}, and displays verified badge.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Stripe API connection failure. System displays: ``Unable to reach payment gateway. Please try again later.''\\ \hline
      A2 & Verification incomplete or exited prematurely. Stripe flags account with pending requirements; system displays ``Action Required'' banner.\\ \hline
      A3 & User is not a Freelancer. API returns HTTP 403 Forbidden; access denied.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{onboardingUrl} & Temporary Stripe-hosted onboarding URL.\\ \hline
      \texttt{isConnected} & Boolean status indicating whether payouts are active (\texttt{true} / \texttt{false}).\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Stripe Account ID linked to user profile.
      \item Payout capabilities verified and enabled.
\end{itemize}

\subsubsection{ View Payout History}

\fnhead{Function Trigger}
A Freelancer clicks the ``Payouts'' tab in their financial dashboard.\newline
\textbf{Navigation path:} Freelancer Dashboard $\rightarrow$ Payments $\rightarrow$ Click ``Payouts Tab'' (\texttt{/freelancer/payments?type=PAYOUT}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Freelancer (\texttt{FREELANCER} role), Administrator.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Prisma ORM layer, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Displays a paginated ledger of all automated bank transfer payouts sent to the Freelancer's Stripe connected account, showing transfer amounts, net earnings, platform commission deductions, and processing statuses.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Payouts tab on the financial transactions dashboard.
      \item Metric cards summarizing Total Withdrawn, Pending Transfers, and Available Balance.
      \item Payouts data table with columns: Date, Transfer Reference, Related Contract/Milestone, Gross Amount, Platform Fee (10\%), Net Payout, Status, and Actions.
      \item Filter pills by status (\texttt{COMPLETED}, \texttt{PENDING}, \texttt{FAILED}).
      \item Pagination controls footer.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client requests \texttt{GET /api/payments/transactions?type=PAYOUT\&page=1\&limit=10}.
      \item \texttt{PaymentService.getTransactions()} filters transactions where \texttt{userId === callerId} and \texttt{type === 'PAYOUT'} (or unrestricted for Admin).
      \item Orders transactions chronologically by \texttt{createdAt desc}.
      \item Computes pagination count in parallel via Prisma count.
      \item Returns HTTP 200 with the payout records array.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint4/ntin/ViewPayoutHistory.png}{Freelancer payout history screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Top row renders cards for Total Earnings Disbursed and Last Payout Date.
      \item Table lists transfer rows with date stamp, milestone title, green net payout amount, and status pill.
      \item Action icon opens granular transfer detail modal.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{page} & Page number (integer, default 1).\\ \hline
      \texttt{limit} & Items per page (integer, default 10, max 50).\\ \hline
      \texttt{status} & Optional filter status (\texttt{COMPLETED}, \texttt{PENDING}, \texttt{FAILED}).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item User must be an authenticated Freelancer or Administrator.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-PAY-03: Freelancers can only view payout transfers associated with their own user account.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Freelancer opens the Payouts tab.
      \item Client requests payout transactions from API.
      \item API queries database and returns paginated payout records.
      \item Client renders payout history table.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Unauthenticated request. API returns HTTP 401; redirects to login.\\ \hline
      A2 & No payouts exist. Client renders empty state: ``No payouts recorded yet.''\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{payouts[]} & Array of payout records with id, amount, netAmount, feeAmount, status, and createdAt.\\ \hline
      \texttt{pagination} & Object containing page, limit, totalItems, and totalPages.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Payout transfer history displayed.
\end{itemize}

\subsubsection{ Fund Milestone}

\fnhead{Function Trigger}
A Client clicks the ``Fund Escrow'' / ``Deposit Funds'' button on an unfunded milestone card.\newline
\textbf{Navigation path:} Contract Detail $\rightarrow$ Milestones Tab $\rightarrow$ Milestone Card $\rightarrow$ Click ``Fund Milestone''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Secondary Actor:} Stripe Payments Service.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Stripe Elements SDK, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Deposits milestone funds into secure platform escrow via Stripe credit card or saved payment method. Securing funds in escrow gives the Freelancer confidence to proceed with deliverable work, knowing payment is guaranteed upon completion approval.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item ``Fund Milestone'' action button on unfunded milestone cards.
      \item Fund Escrow modal dialog displaying milestone amount, escrow terms, and payment method selector.
      \item Stripe Elements embedded card input or saved card selector (e.g. ``Visa ending in 4242'').
      \item Action buttons: ``Confirm \& Pay \$USD'' and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client initiates funding: requests \texttt{POST /api/payments/contracts/:contractId/milestones/:milestoneId/fund/intent} or \texttt{/saved-card}.
      \item \texttt{PaymentService} validates caller is contract's Client and contract platform fee is paid.
      \item Verifies milestone is in \texttt{UNPAID} payment status.
      \item Generates a Stripe PaymentIntent configured with milestone escrow amount and metadata.
      \item Upon card confirmation, Stripe processes payment and triggers escrow deposit.
      \item Database updates milestone \texttt{paymentStatus = FUNDED} and transitions status to \texttt{IN\_PROGRESS}.
      \item Creates ledger transaction record (\texttt{ESCROW\_DEPOSIT}) and notifies Freelancer to begin work.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint4/ntin/FundMilestone.png}{Fund Milestone escrow payment modal}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Modal displays title ``Fund Milestone Escrow'' and milestone name.
      \item Deposit amount card shows total amount to be held in secure escrow.
      \item Payment option: choose saved card or enter new credit card via Stripe Elements.
      \item Primary blue button ``Deposit \$X.00 into Escrow'' with security lock badge.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{milestoneId} & Numeric milestone identifier (integer path parameter).\\ \hline
      \texttt{paymentMethodId} & Optional Stripe payment method ID for saved card charge (string).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be the contract's Client.
      \item Contract platform fee must be settled (\texttt{platformFeeStatus = PAID}).
      \item Milestone payment status must be \texttt{UNPAID}.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-PAY-05: Milestone funds deposited into escrow are held securely until approved, refunded, or resolved via arbitration.
      \item BR-PAY-06: Escrow deposit automatically activates the milestone for work progress.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Client clicks ``Fund Milestone'' on an unfunded milestone card.
      \item System opens Fund Escrow modal with payment method options.
      \item Client selects saved card or enters card details.
      \item Client clicks ``Confirm \& Pay''.
      \item Stripe charges card and confirms PaymentIntent.
      \item System marks milestone \texttt{paymentStatus = FUNDED} and status \texttt{IN\_PROGRESS}.
      \item Modal closes, card turns blue, and Freelancer is notified to start work.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Milestone is already funded. API returns HTTP 422 with error \texttt{MilestoneNotEligibleForFundingException}.\\ \hline
      A2 & Contract platform fee has not been paid. API returns HTTP 422; prompts to pay platform fee first.\\ \hline
      A3 & Card payment declined by issuer. Stripe returns card error; form prompts for alternative card.\\ \hline
      A4 & Caller is not the Client. API returns HTTP 403 Forbidden; access denied.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{paymentIntent} & Stripe PaymentIntent confirmation object with status \texttt{succeeded}.\\ \hline
      \texttt{milestoneStatus} & Updated milestone payment status (\texttt{FUNDED}).\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Milestone escrow funded and transaction logged.
      \item Milestone status transitioned to \texttt{IN\_PROGRESS}.
      \item Freelancer notified.
\end{itemize}

\subsubsection{ Refund Payment}

\fnhead{Function Trigger}
A Client requests a refund for a cancelled milestone, or an Admin executes an agreed escrow refund.\newline
\textbf{Navigation path:} Contract Detail $\rightarrow$ Milestones Tab $\rightarrow$ Funded Milestone $\rightarrow$ Click ``Request Refund''.

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client, Administrator.
      \item \textbf{Secondary Actor:} Stripe Refund Gateway.
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Stripe API SDK, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Refunds funded milestone escrow deposits back to the Client's original payment method when a milestone is mutually cancelled, terminated, or granted a refund under platform arbitration terms.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Refund action button or modal in the contract management workspace.
      \item Refund confirmation dialog detailing refund amount (\$USD), processing timeline (5--10 business days), and original payment method.
      \item Action buttons: ``Confirm Refund'' and ``Cancel''.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client or Admin submits an HTTP request: \texttt{POST /api/payments/contracts/:contractId/milestones/:milestoneId/refund}.
      \item \texttt{PaymentService.refundMilestone()} verifies authorization and milestone eligibility.
      \item Checks that milestone payment status is \texttt{FUNDED}; un-funded or already released milestones are rejected.
      \item Finds original \texttt{ESCROW\_DEPOSIT} transaction and extracts Stripe PaymentIntent ID.
      \item Calls \texttt{stripe.refunds.create()} to initiate refund on original charge.
      \item Inside a database transaction, updates milestone \texttt{paymentStatus = REFUNDED} and records \texttt{REFUND} transaction.
      \item Sends refund receipt notification to the Client.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint4/ntin/RefundPayment.png}{Refund Payment confirmation screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Modal displays refund icon and heading ``Refund Milestone Escrow''.
      \item Summary details refund amount, original deposit date, and destination card.
      \item Warning notes that refund processing typically takes 5--10 days depending on the card issuer.
      \item Buttons: ``Cancel'' and primary orange ``Confirm Refund''.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{contractId} & Numeric contract identifier (integer path parameter).\\ \hline
      \texttt{milestoneId} & Numeric milestone identifier (integer path parameter).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Milestone payment status must be \texttt{FUNDED}.
      \item Milestone funds must not have already been released to the freelancer.
      \item Milestone must not have an active unresolved dispute.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-PAY-07: Released milestone funds cannot be refunded via escrow refund; dispute arbitration is required.
      \item BR-PAY-08: Refunds are credited strictly back to the original funding payment method.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item User initiates refund on eligible funded milestone.
      \item System displays refund confirmation dialog.
      \item User clicks ``Confirm Refund''.
      \item Stripe initiates gateway refund on original charge.
      \item System marks milestone \texttt{paymentStatus = REFUNDED} and logs refund transaction.
      \item Success confirmation appears and Client receives email receipt.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Milestone is already released. API returns HTTP 422 with error \texttt{MilestoneAlreadyReleasedException}; refund blocked.\\ \hline
      A2 & Milestone is not funded. API returns HTTP 422 with error \texttt{MilestoneNotFundedException}.\\ \hline
      A3 & Stripe refund API fails. System displays gateway error and prompts retry.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{refund} & Stripe refund entity with status \texttt{succeeded} and refund ID.\\ \hline
      \texttt{milestoneStatus} & Updated payment status (\texttt{REFUNDED}).\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Milestone payment status updated to \texttt{REFUNDED}.
      \item Gateway refund initiated and ledger record logged.
\end{itemize}

\subsubsection{ Pay Platform Fee}

\fnhead{Function Trigger}
A Client clicks ``Pay Platform Fee'' or is redirected to checkout following mutual contract signing.\newline
\textbf{Navigation path:} Contract Detail (\texttt{/client/contracts/:slug}) $\rightarrow$ Payment Banner $\rightarrow$ Click ``Pay Platform Fee''.

\subsubsection{ Handle Stripe Webhook Event}

\fnhead{Function Trigger}
Stripe asynchronously dispatches an HTTP POST request to the platform webhook endpoint upon payment lifecycle events.\newline
\textbf{Navigation path:} External Payment Gateway $\rightarrow$ System Webhook Endpoint (\texttt{POST /api/payments/webhook}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Stripe Payment Gateway (Automated System).
      \item \textbf{Supporting Systems:} Frevia REST API (NestJS), Stripe Webhook Verifier, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Securely receives and processes asynchronous payment events dispatched by Stripe (e.g. \texttt{payment\_intent.succeeded}, \texttt{payment\_intent.payment\_failed}, \texttt{checkout.session.completed}, \texttt{account.updated}), guaranteeing eventual consistency between gateway state and the platform database.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Automated API endpoint at \texttt{POST /api/payments/webhook} protected by HMAC SHA-256 signature verification.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Server receives raw body payload and \texttt{stripe-signature} header.
      \item \texttt{PaymentService.handleWebhook()} constructs and validates the event using \texttt{stripe.webhooks.constructEvent(payload, signature, secret)}.
      \item Dispatches event handling based on event type:
            \begin{itemize}[leftmargin=1.6em,topsep=2pt,itemsep=2pt,parsep=0pt]
                  \item \texttt{payment\_intent.succeeded}: Marks pending transaction \texttt{COMPLETED} and updates milestone/contract status.
                  \item \texttt{checkout.session.completed}: Completes platform fee or milestone funding session.
                  \item \texttt{account.updated}: Updates freelancer's \texttt{chargesEnabled} and \texttt{payoutsEnabled} status.
            \end{itemize}
      \item Returns HTTP 200 with acknowledgment \texttt{\{ received: true \}}.
\end{itemize}

\fnhead{Screen Layout (Mock-up Description)}
\screenfigure[0.95]{image/screenshot/sprint4/ntin/HandleStripeWebhookEvent.png}{Stripe webhook events monitoring log}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Admin developer portal view displays the Stripe webhook events log.
      \item Table shows Event Type, Event ID, Processing Timestamp, and Status (200 OK).
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{stripe-signature} & HMAC SHA-256 signature header generated by Stripe.\\ \hline
      \texttt{payload} & Raw JSON event payload dispatched by Stripe.\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Webhook signature header must match the configured webhook signing secret.
      \item Event timestamp must be fresh to prevent replay attacks.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-PAY-18: Webhook handlers must be idempotent, safely processing duplicate events without re-applying state changes.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Stripe dispatches webhook event to \texttt{/api/payments/webhook}.
      \item Server verifies HMAC signature.
      \item Server processes event payload and updates database records.
      \item Server returns HTTP 200 acknowledgment.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Signature invalid or missing. Server rejects with HTTP 400 Bad Request and error \texttt{WebhookSignatureInvalidException}.\\ \hline
      A2 & Unhandled event type. Server returns HTTP 200 acknowledgment without modifying state.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{received} & Boolean acknowledgment confirmation (\texttt{true}).\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Database records synchronized with gateway event.
\end{itemize}

\subsubsection{ Sync Payment Intent Status}

\fnhead{Function Trigger}
A Client returns from a Stripe Checkout redirect, or manually triggers payment reconciliation.\newline
\textbf{Navigation path:} Contract Detail $\rightarrow$ Return from Checkout $\rightarrow$ Automatic Sync Trigger (\texttt{POST /api/payments/checkout-sessions/:sessionId/sync}).

\fnhead{Function Description}

\sublabel{Actors / Roles}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item \textbf{Primary Actor:} Client (\texttt{CLIENT} role).
      \item \textbf{Supporting Systems:} Frevia Web application (Next.js), Frevia REST API (NestJS), Stripe API SDK, Prisma ORM, and PostgreSQL database.
\end{itemize}

\sublabel{Purpose}
\noindent Immediately synchronizes local transaction and milestone states directly with Stripe API following checkout redirect, eliminating dependency on asynchronous webhook latency so the user immediately sees updated contract/milestone statuses.

\sublabel{Interface}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Checkout return page rendering loading spinner: ``Verifying payment confirmation\ldots''.
      \item Success redirect to contract workspace with green confirmed banner.
\end{itemize}

\sublabel{Data Processing Overview}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Client requests \texttt{POST /api/payments/checkout-sessions/:sessionId/sync} or \texttt{/intents/:id/sync}.
      \item \texttt{PaymentService.syncCheckoutSession()} queries Stripe API directly via \texttt{stripe.checkout.sessions.retrieve()}.
      \item Checks \texttt{session.payment\_status === 'paid'}.
      \item If local transaction is pending, transitions transaction to \texttt{COMPLETED} and marks milestone \texttt{FUNDED} or platform fee \texttt{PAID}.
      \item Returns HTTP 200 with synced transaction entity.
\end{itemize}

\screenfigure[0.95]{image/screenshot/sprint4/ntin/SyncPaymentIntentStatus.png}{Payment reconciliation confirmation screen}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Screen displays animated checkmark and heading ``Payment Verified!''.
      \item Milestone escrow deposit status confirms funds secured.
      \item ``Return to Contract Workspace'' button.
\end{itemize}

\fnhead{Function Details}

\sublabel{Input Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{sessionId} & Stripe Checkout session identifier (string path parameter).\\ \hline
\end{specdatatable}

\sublabel{Validation Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Caller must be the authenticated Client.
      \item Session ID must be valid in Stripe.
\end{itemize}

\sublabel{Business Rules}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]\brrulelist
      \item BR-PAY-19: Synchronizing reconciles state immediately without waiting for webhook delivery.
\end{itemize}

\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.8em,topsep=3pt,itemsep=2pt,parsep=0pt]
      \item Client finishes checkout and returns to Frevia.
      \item Client triggers session sync.
      \item Server queries Stripe API directly and confirms payment.
      \item Server updates local records and returns confirmation.
      \item Client navigates to contract workspace with active milestone state.
\end{enumerate}

\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
      A1 & Payment session unpaid or expired. Server reports unpaid status; prompts client to complete payment.\\ \hline
      A2 & Invalid session ID. Server returns HTTP 404 Not Found.\\ \hline
\end{flowtable}

\sublabel{Output Data}
\begin{specdatatable}{Data Name}{Description}
      \texttt{status} & Synchronized payment status (\texttt{paid} / \texttt{succeeded}).\\ \hline
      \texttt{transaction} & Updated transaction record.\\ \hline
\end{specdatatable}

\sublabel{Post-Conditions}
\begin{itemize}[leftmargin=1.6em,topsep=3pt,itemsep=2pt,parsep=0pt,label=$\bullet$]
      \item Local database synchronized with Stripe state immediately.
\end{itemize}
