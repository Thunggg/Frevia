\subsection{Following Management}
\Needspace{10\baselineskip}
\subsubsection{Function: View Following List (UC-29.01)}
\label{fn:nhuy-uc-29-01}

\Needspace{7\baselineskip}
\fnhead{Function Trigger}
The actor selects View Following List. Navigation: /client/profile (Following); /profiles/[id].

\Needspace{7\baselineskip}
\fnhead{Function Description}
\Needspace{5\baselineskip}
\sublabel{Actors / Roles}
Client.
\Needspace{5\baselineskip}
\sublabel{Purpose}
Load freelancer relationships owned by the current Client and show the following state.
\Needspace{5\baselineskip}
\sublabel{Interface and Data Processing}
{\small\texttt{GET /\allowbreak{}following/\allowbreak{}freelancers}}. The browser calls the Next.js BFF, which forwards authenticated requests to the NestJS API. The server derives the acting user from authentication and accesses User, FollowFreelancer, Notification. Route IDs are validated independently from owner IDs.

\Needspace{7\baselineskip}
\fnhead{Screen Layout (Mock-up Description)}
\begin{center}
\fbox{\begin{minipage}{0.88\linewidth}
\textbf{View Following List}\par\smallskip
Following cards with profile links and Unfollow; discovery section and Follow action; empty-state message.\par\smallskip
\textit{Schematic interface description, not an application screenshot.}
\end{minipage}}
\end{center}

\Needspace{7\baselineskip}
\Needspace{18\baselineskip}
\fnhead{Function Details}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Input Data}
\begin{specdatatable}{Data}{Definition}
Selection & Current account or selected profile/contract; no pagination is assumed unless exposed by the endpoint. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Validation and Business Rules}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Only a Client follows or unfollows an active freelancer; self-follow is rejected.
\item A unique (clientId, freelancerId) mapping prevents duplicates.
\item Create the follow and its recipient notification together in a transaction.
\item Unfollow hard-deletes the mapping without deleting either user.
\end{itemize}
\Needspace{5\baselineskip}
\sublabel{Normal Flow}
\begin{enumerate}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item The actor opens /client/profile (Following); /profiles/[id] and selects View Following List.
\item The application submits the selected identifier or list filters.
\item The API checks authentication where required, authorization, resource existence and input validity.
\item Load freelancer relationships owned by the current Client and show the following state.
\item The screen renders the response, or an explicit empty state for a valid empty collection.
\end{enumerate}
\Needspace{5\baselineskip}
\sublabel{Alternative Flow}
Show an informative empty state for a valid empty result and allow retry after a transport failure.
\Needspace{5\baselineskip}
\sublabel{Abnormal Flow / Exception Handling}
\begin{flowtable}{Case}{Description}
E1 & Missing or expired authentication, or insufficient role/ownership: deny the operation and do not change data. \\ \hline
E2 & Missing, deleted or inaccessible resource: show a not-found result. \\ \hline
A1 & A valid empty collection displays an empty state; it must not be treated as a missing account. \\ \hline
E4 & Database, network or storage failure: report a retryable error; do not report success or terminate the API process. \\ \hline
\end{flowtable}
\Needspace{5\baselineskip}
\Needspace{14\baselineskip}
\sublabel{Output Data}
\begin{specdatatable}{Data}{Definition}
Result & Load freelancer relationships owned by the current Client and show the following state. \\ \hline
Failure & Structured error without sensitive data; no successful UI state when the operation failed. \\ \hline
\end{specdatatable}
\Needspace{5\baselineskip}
\sublabel{Acceptance Criteria}
\begin{itemize}[leftmargin=1.7em,itemsep=2pt,topsep=3pt]
\item Successful view following list produces the documented response and survives a reload where data is persisted.
\item An unauthorized actor cannot access or modify the resource.
\item Invalid input and missing resources do not create a false success state or expose sensitive data.
\end{itemize}
