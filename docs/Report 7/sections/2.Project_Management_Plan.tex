\section{Development Approach}

To deliver a multi-role marketplace spanning web frontend, RESTful/WebSocket backend, payment escrow orchestration, and external AI microservices within a 15-week capstone window, Group \texttt{SEP490\_04} adopted the \textbf{Agile Scrum} framework:

\begin{itemize}[leftmargin=1.0cm, itemsep=4pt]
    \item \textbf{Iterative 2-Week Sprints:} Product delivery was decomposed into \textbf{five progressive increments} (Sprints 1--5). Each sprint followed a disciplined cadence of Sprint Planning, daily stand-up synchronization, bi-weekly Sprint Reviews with the Supervisor, and Sprint Retrospectives.
    \item \textbf{Monorepo \& Feature-Branch Workflow:} All application workspaces (\texttt{apps/web}, \texttt{apps/api}, \texttt{packages/shared-type}, \texttt{packages/ui}) were coordinated through \textbf{Turborepo} and \textbf{pnpm}. Every Use Case followed the branch naming rule \texttt{uc-[id]-[action-name]} and merged only after peer code review.
    \item \textbf{Automated Quality Gates \& Environment Parity:} Before merging or closing any task, developers ran static linting (\texttt{pnpm lint}), TypeScript type verification (\texttt{pnpm check-types}), Jest unit suites (\texttt{pnpm test}), and multi-service \texttt{docker compose build} checks.
    \item \textbf{Living Documentation:} Software Requirements (SRS), Design (SDS), Test Cases, and User Guides were updated iteratively alongside each functional sprint rather than deferred to the end of the project.
\end{itemize}
