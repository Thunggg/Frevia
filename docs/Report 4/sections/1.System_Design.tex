\section{System Design}

\subsection{System Architecture}

The Frevia system follows an N-layer architecture, separating the client applications, presentation layer, business logic layer, data access layer, shared library layer, and external integration systems (Figure~\ref{fig:arch:overall}). The system also natively integrates with PostgreSQL, Cloudinary, Stripe, Google OAuth 2.0, Nodemailer, Infisical, and local Python FastAPI AI microservices backed by Ollama LLM.

\kfig{0.95\textwidth}{images/architecture/frevia-overall-architecture}{System Architecture Diagram}{fig:arch:overall}

\subsubsection*{Client Application}
Frevia delivers a unified, responsive web application catering to five actor roles: Guest, Client, Freelancer, Expert, and Administrator.
\begin{itemize}[leftmargin=*]
    \item \textbf{Web Client:} Developed with Next.js 16 (React 19) and TypeScript utilizing the App Router architecture. It consists of:
    \begin{itemize}[leftmargin=*]
        \item \textit{Pages and Screens:} Built with React Server Components (RSC) for optimal search engine indexing and rapid initial page loads, complemented by Client Components for interactive user interfaces. Styled using TailwindCSS 4 and the \texttt{@repo/ui} component library (based on shadcn/ui), and localized into English and Vietnamese via \texttt{next-intl}.
        \item \textit{Hooks and State Management:} Driven by TanStack Query (React Query) for server state caching, background revalidation, and optimistic mutations. Client-side form validation is managed via \texttt{react-hook-form} paired with Zod schemas.
        \item \textit{API Services (\texttt{apiRequests/}):} A typed HTTP client layer encapsulating \texttt{lib/http.ts}. It automatically binds JWT access tokens to request headers, transparently handles token refreshes upon expiration, and interfaces with the Socket.io client for real-time messaging and notifications.
    \end{itemize}
\end{itemize}
The client application transmits requests exclusively over HTTPS REST APIs and displays returned responses. It contains no direct database access logic and enforces no authoritative business rules.

\subsubsection*{Presentation Layer}
The Presentation Layer is implemented within the NestJS 11 Web Server Application (\texttt{apps/api}). It serves as the entry boundary for incoming client requests and real-time events:
\begin{itemize}[leftmargin=*]
    \item \textbf{Controllers:} Expose structured RESTful API endpoints (versioned under \texttt{/api/v1}), receive client requests, bind validated request payloads, and delegate processing to domain services.
    \item \textbf{Authentication and Authorization Guards:} Intercept requests to verify JWT tokens and enforce role-based access control (\texttt{RoleGuard}) and fine-grained permission checks (\texttt{PermissionGuard}).
    \item \textbf{Validation and Serialization:} Validates incoming request payloads using shared Zod DTOs and sanitizes outgoing responses using the global \texttt{ZodSerializerInterceptor}.
    \item \textbf{Socket.io Gateway:} Manages real-time bidirectional WebSocket connections for peer-to-peer conversations and immediate notification pushes.
\end{itemize}

\subsubsection*{Business Logic Layer}
The Business Logic Layer represents the core of the Frevia platform, encapsulating business rules, ownership verifications, and deterministic domain state machines across 33 route modules:
\begin{itemize}[leftmargin=*]
    \item \textbf{Authentication and Access Control Module:} Manages user registration, OTP verification, credential login, Google OAuth federated sign-in, token refresh, device sessions, roles, and granular permissions.
    \item \textbf{User and Profile Management Module:} Handles administrator user accounts, account profiles, freelancer professional portfolios, CV uploads, and expert consultation profiles.
    \item \textbf{Job and Proposal Management Module:} Governs client job postings, faceted job browsing, bookmarking, freelancer proposal submissions, interviews, and proposal acceptance/rejection workflows.
    \item \textbf{Contract and Milestone Module:} Enforces contract lifecycle transitions (draft, agreement, digital signature, completion, cancellation) and milestone delivery reviews.
    \item \textbf{Payment and Escrow Module:} Integrates Stripe Checkout for milestone escrow funding, platform fee collections, dispute fee handling, and automated Stripe Connect payouts to freelancer bank accounts.
    \item \textbf{Communication and Community Module:} Facilitates real-time direct messaging, multi-category discussion forums, post interactions, and automated user notification feeds.
    \item \textbf{Dispute Arbitration Module:} Provides formal dispute filing, evidence attachment, and administrator arbitration workflows.
\end{itemize}

\subsubsection*{Data Access Layer}
The Data Access Layer encapsulates all persistence logic using the Repository Pattern combined with Prisma 7 ORM and the native PostgreSQL driver adapter (\texttt{@prisma/adapter-pg}):
\begin{itemize}[leftmargin=*]
    \item \textbf{Repositories:} Implement dedicated query methods, data filtering, pagination helpers, and soft-delete semantics (\texttt{isDeleted}). Controllers and services are strictly decoupled from raw database queries.
    \item \textbf{Transaction Management:} Wraps complex multi-table workflows (such as escrow fund transfers, contract creation, and user onboarding cascades) inside atomic \texttt{\$transaction} blocks to maintain absolute relational integrity.
\end{itemize}

\subsubsection*{Shared Library Layer}
The Shared Library Layer provides shared definitions and cross-cutting utilities utilized across the application tiers:
\begin{itemize}[leftmargin=*]
    \item \textbf{Contract Single Source of Truth (\texttt{@shared/types}):} Monorepo package defining shared Zod validation schemas, TypeScript interfaces, system constants, database enumerations, and standardized error codes.
    \item \textbf{Backend Cross-Cutting Infrastructure (\texttt{src/shared}):} Contains global exception filters, authentication decorators, Cloudinary storage wrappers, Nodemailer integration, and the shared Prisma client service.
\end{itemize}

\subsubsection*{Data Storage}
\begin{itemize}[leftmargin=*]
    \item \textbf{PostgreSQL Database:} Stores all persistent platform data across 72 relational domain models and 43 enumerations, maintaining relational integrity with foreign keys, compound indexes, and audit timestamps.
    \item \textbf{Cloudinary Object Storage:} Dedicated cloud repository storing binary multimedia files, including user profile avatars, citizen identity document photographs (CCCD), candidate resumes, and contract deliverable archives.
\end{itemize}

\subsubsection*{External Systems and Internal AI Services}
\begin{itemize}[leftmargin=*]
    \item \textbf{Google OAuth 2.0:} Facilitates federated single sign-on. The frontend retrieves a Google authorization credential, which the backend verifies to establish an authenticated Frevia session.
    \item \textbf{Stripe:} Processes online financial transactions, managing escrow funding via Stripe Checkout, platform fee collection, dispute deposits, and automated freelancer payouts via Stripe Connect. Status updates are synchronized securely via cryptographic webhooks.
    \item \textbf{Internal AI Microservices (FastAPI \& Python):}
    \begin{itemize}[leftmargin=*]
        \item \textit{eKYC ID Verification (\texttt{id-verification}, port 8001):} Employs RapidOCR for card text extraction, InsightFace for biometric facial embeddings, and MediaPipe for liveness detection to detect fraudulent identity documents.
        \item \textit{Section-Aware CV and Job Matching (\texttt{cv-matching}, port 8000):} BGE-M3 embeddings, ChromaDB vector indexing, and local Ollama LLM inference to parse candidate CVs and compute semantic candidate-to-job matching scores.
        \item \textit{AI Content Moderation (\texttt{ai-moderation}, port 8001):} Automatically scores community forum posts and comments, quarantining toxic or abusive content into the administrative review queue.
    \end{itemize}
    \item \textbf{SMTP Mail Service (Nodemailer):} Delivers transactional notifications, one-time passwords (OTP), and contract status alerts.
    \item \textbf{Infisical:} Secure secrets manager that injects environment variables and credentials into application containers at startup.
\end{itemize}

\subsubsection*{Request-Response Data Flow}
A typical user request originates on a Next.js Page or Screen, triggers a TanStack Query hook, and invokes a typed API method in \texttt{apiRequests/}. The service binds the JWT access token and issues an HTTPS REST call to the NestJS backend. The request passes through the Authentication Guard, Role/Permission Guards, and Zod DTO validation before reaching the appropriate Controller. The Controller delegates execution to the Service Layer, which validates business rules and state machines, then commands the Repository to execute queries through Prisma 7 to PostgreSQL. The resulting entity follows the reverse path, is sanitized by the Zod serializer interceptor, and is returned as a uniform JSON response to update the client-side cache and re-render the user interface. Real-time events follow an asynchronous parallel path via the Socket.io Gateway.

\subsection{Package Diagram}
\label{subsec:package-diagram}

The Frevia repository is organized as a high-cohesion monorepo managed with \textbf{pnpm workspaces} and \textbf{Turborepo} (Figure~\ref{fig:arch:packages}). This structure cleanly separates the presentation tier (\texttt{apps/web}), the application tier (\texttt{apps/api}), the shared workspace packages (\texttt{packages/*}), and the independent AI microservices (\texttt{ai-services/}).

\kfig{0.95\textwidth}{images/architecture/frevia-package-diagram}{Package diagram}{fig:arch:packages}

\subsubsection*{Monorepo Architecture Rules}
The monorepo enforces four key architectural rules illustrated in Figure~\ref{fig:arch:packages}:
\begin{enumerate}[leftmargin=*]
    \item \textbf{Strict Downward Dependencies:} Applications (\texttt{apps/web} and \texttt{apps/api}) depend on shared packages (\texttt{packages/*}); a shared package never imports code or types from an application.
    \item \textbf{Module Isolation:} Domain route modules inside \texttt{apps/api/src/routes/} are strictly decoupled and never import controllers, services, or repositories from sibling modules. Cross-module data flows exclusively through database relationships at the Prisma ORM schema level.
    \item \textbf{Universal Configuration:} Common configurations for linting (\texttt{@repo/eslint-config}) and TypeScript compilation (\texttt{@repo/typescript-config}) are inherited by all workspaces to guarantee uniform code quality.
    \item \textbf{Independent AI Service Boundaries:} Python-based AI microservices (\texttt{id-verification}, \texttt{cv-matching}, \texttt{ai-moderation} backed by Ollama) reside in \texttt{ai-services/} and communicate with the backend via standard HTTP REST endpoints, maintaining complete independence from the TypeScript pnpm workspaces.
\end{enumerate}
