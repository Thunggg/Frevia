\section{Scope of Testing}

\subsection{Testing Scope}

\subsubsection{In-Scope Testing}

Testing for the \textbf{Frevia -- Verified Freelance Marketplace Platform} (Project Code: \texttt{SEP490\_04}) covers all functional and non-functional deliverables across the five project sprints:

\begin{itemize}
  \item \textbf{Identity, Authentication, and Access Control (FE-01 to FE-09):}
  \begin{itemize}
    \item Email and password registration with one-time-code (OTP) email verification, Google OAuth 2.0 sign-in, and linking a Google identity to an existing account.
    \item JWT access and refresh token authentication, persisted session management (listing active sessions, viewing device/IP details, and revoking individual sessions), password reset via OTP, and password change.
    \item Multi-role membership (\texttt{CLIENT}, \texttt{FREELANCER}, \texttt{ADMIN}, and custom administrative roles), joining additional roles, active session role switching, and dynamic data-driven RBAC permission validation (\texttt{HTTP method} + \texttt{path} + \texttt{module}).
  \end{itemize}
  \item \textbf{User Profiles, Portfolios, and AI CV Analysis (FE-10 to FE-20):}
  \begin{itemize}
    \item Account profile management with avatar/cover uploads, freelancer profiles (professional title, bio, education, certifications, languages, work experience, skills with proficiency levels 1--10, and portfolio items), client company profiles, and expert directory profiles.
    \item Profile completion and strength scoring, administrative approval workflow for profile revisions, PDF curriculum vitae upload (up to 10~MB), and AI-assisted CV skill extraction.
  \end{itemize}
  \item \textbf{Electronic Identity Verification / eKYC (FE-21 to FE-23):}
  \begin{itemize}
    \item Submission of front/back identity card images, selfie capture, and active/passive liveness frames; AI verification pipeline (OCR, QR code reading, face matching, tamper detection); and the administrative review queue.
  \end{itemize}
  \item \textbf{Job Marketplace, Proposals, Contracts, and Milestones (FE-24 to FE-47):}
  \begin{itemize}
    \item Fixed-price job creation, editing, soft deletion, status lifecycle, stable slug generation, multi-criteria public job search, job bookmarks, and saved searches.
    \item Proposal drafting, submission, editing, withdrawal, and expiry; client proposal evaluation and hiring decision; dual-signature contract execution; USD~10.00 platform fee tracking; and milestone creation, funding state transitions, work submission, change requests, and approval.
  \end{itemize}
  \item \textbf{Stripe Escrow Payments, Disputes, and Reviews (FE-48 to FE-65):}
  \begin{itemize}
    \item Stripe Connect Express onboarding, saved payment methods, platform fee and milestone funding via \texttt{PaymentIntent} and \texttt{Checkout Session}, milestone transfers on release, refunds, raw-body webhook signature verification, and ledger reconciliation.
    \item Milestone dispute filing with evidence, respondent defence within deadlines, decision review escalation, administrative arbitration with split payouts, and post-contract reviews/ratings.
  \end{itemize}
  \item \textbf{Real-Time Communication, Community Forum, and Administration (FE-66 to FE-83):}
  \begin{itemize}
    \item Authenticated Socket.IO WebSocket messaging (1-on-1 conversations, file attachments, read receipts, typing indicators, pin/hide/delete) and persistent notifications.
    \item Community forum browsing, rich-text post creation (Tiptap), comments, likes, reporting, AI moderation scoring, and administrative moderation/trash management.
    \item Administrative management of users, roles, permissions, sessions, job categories, master skill catalogue (soft-delete and restore), and advertisement banners across five placement zones, together with bilingual localization (\texttt{en}/\texttt{vi}) and responsive light/dark themes.
  \end{itemize}
\end{itemize}

\subsubsection{Out-of-Scope Testing}

In accordance with the project scope limitations defined in Report 1, the following areas are excluded from testing:

\begin{itemize}
  \item \textbf{Third-Party Core Infrastructure Internals:} Internal uptime, cryptographic engines, and settlement clearing networks of external service providers (Stripe live banking rails, Google OAuth identity servers, Cloudinary CDN infrastructure, and external SMTP servers).
  \item \textbf{Hourly Contracts and Multi-Currency Settlement (LI-01 to LI-04):} Hourly billing, automated time-tracking diaries, non-USD currency conversion, domestic e-wallets, direct bank wire transfers, and cryptocurrency settlement.
  \item \textbf{Machine Learning Model Training and Foreign ID Documents (LI-05 to LI-07):} Training or fine-tuning underlying neural network weights for OCR, liveness, or CV parsing, as well as identity verification for non-Vietnamese passports or driver's licences.
  \item \textbf{Native Mobile Clients and Multi-Replica Clustering (LI-09, LI-13):} Native iOS/Android mobile applications, multi-node horizontal load balancing, sticky session clustering, and distributed Redis WebSocket adapters.
  \item \textbf{Unexposed Database Entities (LI-11):} Schema tables reserved for future releases that are not exposed through the current API or UI (\texttt{totp\_secrets}, \texttt{invoices}, \texttt{certificates}, \texttt{contract\_terms\_templates}, \texttt{job\_alerts}, \texttt{banned\_keywords}, and \texttt{system\_settings}).
\end{itemize}

\subsection{Testing Constraints and Assumptions}

\textbf{Assumptions}
\begin{itemize}
  \item Third-party sandbox services (Stripe Test Mode API, Google OAuth 2.0 test credentials, Cloudinary media storage, and SMTP test relay) remain available and behave consistently with their documented contracts during test execution.
  \item The PostgreSQL test database is initialized from Prisma migrations and populated deterministically using the repository seed scripts (\texttt{seed}, \texttt{seed:permissions}, \texttt{seed:job-categories}, \texttt{seed:jobs-dataset}, and \texttt{seed:freelancers-dataset}) before executing system and regression test suites.
  \item External AI microservices for eKYC verification and CV skill extraction are reachable over HTTP (\texttt{FREVIA\_AI\_URL}) or simulated with deterministic test fixtures so that both automated scoring and administrative manual review fallbacks can be verified.
  \item Evaluators and UAT participants use modern desktop/mobile browsers (Google Chrome or Microsoft Edge) with camera permissions enabled when testing the eKYC selfie and liveness capture steps.
\end{itemize}

\textbf{Constraints}
\begin{itemize}
  \item \textbf{Sandbox Payment Restriction:} All financial flows (platform fee payment, milestone funding, freelancer payouts, refunds, and dispute split settlements) must be executed strictly in Stripe Test Mode using test cards; real banking networks cannot be exercised.
  \item \textbf{Time-Dependent Business Rules:} Multi-day deadlines (such as proposal expiration, 72-hour dispute fee payment windows, and arbitration defence deadlines) cannot be waited on in real time and require controlled timestamp adjustments in the test database.
  \item \textbf{Document \& Camera Hardware Dependency:} Automated eKYC OCR and liveness detection depend on physical camera quality and Vietnamese citizen ID card formatting; edge cases with damaged or low-light documents rely on curated image fixtures.
  \item \textbf{Single-Instance Deployment Topology:} Testing is conducted on a single container host with in-memory WebSocket room state, bounding load testing to single-node concurrency limits.
\end{itemize}

\section{Test Strategy}

\subsection{Testing Types}

\subsubsection{Unit Testing}
\begin{itemize}
  \item \textbf{Objective:} Verify the internal logic, state validations, data transformations, and error handling of individual methods in NestJS services, repositories, guards, and utilities in isolation from external infrastructure.
  \item \textbf{Technique:}
  \begin{itemize}
    \item \textbf{Equivalence Partitioning \& Boundary Value Analysis:} Partitioning inputs into valid values, empty/whitespace strings, null/undefined parameters, pagination bounds (\texttt{page = 1}, \texttt{limit = 10}, maximum page size), skill proficiency limits (\texttt{1} to \texttt{10}), and file size limits (\texttt{10~MB}).
    \item \textbf{White-Box Branch \& Mock-Based Exception Testing:} Mocking \texttt{PrismaService}, \texttt{JwtService}, and external adapters via \texttt{jest.fn()} to exercise normal paths (\texttt{N}), abnormal exception branches (\texttt{A}), and boundary conditions (\texttt{B}).
  \end{itemize}
  \item \textbf{Completion Criteria:}
  \begin{itemize}
    \item 100\% pass rate across all 507 unit test cases (\texttt{UF-01} to \texttt{UF-84}) documented in \texttt{Report5\_Unit Test.xls}.
    \item Minimum 80\% code coverage on core business logic modules and zero lint or TypeScript compilation errors.
  \end{itemize}
\end{itemize}

\subsubsection{Integration Testing}
\begin{itemize}
  \item \textbf{Objective:} Validate that interacting controllers, services, repositories, Prisma database transactions, WebSocket gateways, and third-party adapters exchange data accurately and preserve relational integrity.
  \item \textbf{Technique:}
  \begin{itemize}
    \item \textbf{Bottom-Up \& Contract-First API Testing:} Testing repository classes against a real PostgreSQL instance first, followed by HTTP endpoint verification via Supertest and Postman against shared \texttt{@shared/types} Zod schemas.
    \item \textbf{Transactional \& Webhook Event Simulation:} Executing multi-table Prisma transactions and replaying signed Stripe webhook payloads to verify idempotency and ledger consistency.
  \end{itemize}
  \item \textbf{Completion Criteria:}
  \begin{itemize}
    \item 100\% of API endpoints, database migrations, and webhook handlers execute without unhandled exceptions or schema mismatches.
    \item All multi-actor state machines (Job, Proposal, Contract, Milestone, Dispute) persist accurate state across module boundaries.
  \end{itemize}
\end{itemize}

\subsubsection{System Testing}
\begin{itemize}
  \item \textbf{Objective:} Verify that the fully integrated Frevia web application satisfies all functional and non-functional requirements specified in the Software Requirement Specification (Report 3).
  \item \textbf{Technique:}
  \begin{itemize}
    \item \textbf{Black-Box Use-Case \& Scenario Testing:} Executing end-to-end test procedures across all 14 functional modules and 84 features from the user interface through to the database.
    \item \textbf{Role-Based Negative \& Exploratory Testing:} Exercising protected pages and API endpoints with different active roles (\texttt{GUEST}, \texttt{CLIENT}, \texttt{FREELANCER}, \texttt{ADMIN}) to verify RBAC enforcement, validation feedback, and empty/error UI states.
  \end{itemize}
  \item \textbf{Completion Criteria:}
  \begin{itemize}
    \item 100\% of the 411 system test cases in \texttt{Report5\_Test Report.xlsx} pass (\texttt{411/411 Passed}).
    \item Zero open Critical or Major defects prior to Sprint Review and final release.
  \end{itemize}
\end{itemize}

\subsubsection{User Acceptance Testing (UAT)}
\begin{itemize}
  \item \textbf{Objective:} Confirm that the delivered platform meets business workflows, usability expectations, and domain requirements from the perspective of end users (Clients, Freelancers, Administrators) and the project supervisor.
  \item \textbf{Technique:}
  \begin{itemize}
    \item \textbf{Incremental Sprint Reviews \& End-to-End Walkthroughs:} Live demonstrations on the staging environment at the end of each sprint, followed by structured UAT scenarios in Sprint 5 with representative Clients and Freelancers completing full marketplace lifecycles.
  \end{itemize}
  \item \textbf{Completion Criteria:}
  \begin{itemize}
    \item At least 95\% of core business workflows are accepted on the first walkthrough, with 100\% of reported UAT feedback resolved before final submission.
    \item Formal acceptance sign-off from the Product Owner (\texttt{Pham Kha Vy}) and Supervisor (\texttt{Cao Hong Nga}).
  \end{itemize}
\end{itemize}

\subsubsection{Non-Functional Testing}
\begin{itemize}
  \item \textbf{Objective:} Ensure that the system satisfies security, access control, query performance, bilingual localization, and container deployment reliability standards.
  \item \textbf{Technique:}
  \begin{itemize}
    \item \textbf{Security \& Authorization Testing:} Attempting privilege escalation (calling administrative routes with client/freelancer tokens, mutating another user's resources, replaying revoked session tokens, and sending unsigned webhook requests).
    \item \textbf{Performance \& Pagination Verification:} Verifying response times on indexed list endpoints (jobs, proposals, forum posts, users, skills, categories) and concurrent Socket.IO messaging sessions.
    \item \textbf{Localization \& Cross-Browser Testing:} Running automated i18n checks (\texttt{check-i18n} and \texttt{check-icu}) and validating UI rendering across Chrome, Edge, and Firefox in English and Vietnamese.
  \end{itemize}
  \item \textbf{Completion Criteria:}
  \begin{itemize}
    \item 100\% of unauthorized requests are blocked with \texttt{401 Unauthorized} or \texttt{403 Forbidden}.
    \item List endpoints respond within $< 500$~ms on staging, and 100\% of English/Vietnamese translation keys are synchronized.
  \end{itemize}
\end{itemize}
